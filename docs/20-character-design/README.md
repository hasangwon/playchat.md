## 2. 제작 파이프라인 (8단계)

작품 1개 = `characters/<slug>/` 폴더 1개. 각 단계의 산출물을 그 폴더에 쓴다.

| 단계 | 할 일 | 산출물 | 통과 기준(한 줄) |
|---|---|---|---|
| ① 컨셉 | 훅·관계·타깃·장르·유형(1:1/시뮬) 결정, 제목·한줄소개 초안 | `character.md` 상단 컨셉 블록 | 썸네일+한줄소개만 보고 "내가 뭘 하게 되는지" 1초 안에 보이는가 |
| ② 배경 | 시대·장소·규칙 3줄, 금지 요소, 시작 시점의 긴장 | `character.md` 세계관 블록 | 매 턴 필요한 것만 남고 나머지는 로어북 후보로 분리됐는가 |
| ③ 프롬프트 | 기본정보→외모→성격→말투→관계→관계 단계→행동 규칙→금지→출력 형식 | `character.md` 프롬프트 블록 | 플랫폼 권장 분량의 60~70% 이내, 말투에 실제 대사 2~3줄 |
| ④ 로어북 | 조건부 정보(인물·장소·사건·아이템·비밀)를 엔트리로 분할 | `lorebook.md` | 키워드가 "유저가 실제로 칠 단어"인가, 중요 항목이 위에 있는가 |
| ⑤ 첫 메시지 | 상황→캐릭터 등장→공 넘기기. 복수 시작점이면 장면별로 | `scenes/01-*.md` … | 유저의 행동·대사·감정을 한 줄도 쓰지 않았는가 |
| ⑥ 예시 대화 | 서로 다른 무드 3~5개, 유저가 안 쓸 대사로 | `character.md` 예시 블록 | 모든 예시가 같은 행동으로 끝나지 않는가 |
| ⑦ 유저 페르소나/메모리 | 추천 페르소나(케이브덕 300자)·대화 프로필, 요약 주기, 상태창/위젯 설계 | `character.md` 유저 블록 | 관계·거리감이 비어 있지 않은가 |
| ⑧ 테스트 | 새 채팅 5회 리롤 → 20~30턴 → 50턴 이후. 한 번에 하나만 수정 | `status.md` 테스트 기록 | `08-testing-qa.md` 최종 체크리스트 전부 통과 |

순서 메모 [커뮤니티, research/03 10-1 뤼튼갤 42661]: 상세 규칙 → 시작 상황 → **테스트** → 수정 → 키워드북 → **테스트** → 수정 → 이미지 → **테스트**. 테스트를 단계 사이에 끼운다.

## 3. 고품질 캐릭터 10가지 조건 [종합]

research/03 부록 B를 실무 점검 문항으로 바꾼 것. 공개 전 10개 모두 "예"여야 한다.

1. **1초 훅** — 썸네일(얼굴 크게)·한줄소개(말투가 들리는 문장)·인트로가 같은 약속을 하는가.
2. **유저 중심 설계** — 유저의 역할·관계·첫 거리감(경계/호의/친함)을 캐릭터 설정보다 먼저 정했는가.
3. **상시 프롬프트는 가볍게** — 플랫폼 권장 분량의 60~70%만 쓰고 나머지는 로어북으로 보냈는가.
4. **말투는 형용사가 아니라 재료로** — 1인칭·호칭·어미 2~3개·입버릇·실제 대사 2~3줄이 있는가.
5. **첫 메시지는 응답의 본보기** — 원하는 길이·형식·시점·말투를 담고, 유저 행동은 쓰지 않고, 열린 비트로 끝나는가.
6. **예시 대화는 무드 3~5개** — 유저가 쓰지 않을 대사로, "제안하고 멈추는" 역할 분담을 보여주는가.
7. **규칙은 5~10개, 명령문** — 조건·분기·변화 후 출력까지 적었는가. 금지보다 원하는 행동을 긍정문으로 썼는가.
8. **로어북 키워드는 적당히 구체적** — 유저가 실제로 칠 단어+별칭, 중요한 것부터 위로, 동시 활성 상한을 아는가.
9. **기억은 분산 저장** — 프롬프트(항상)/로어북(조건)/유저노트·메모리(진행)/시작 상황(초반만) + 주기 요약이 설계돼 있는가.
10. **한 번에 하나씩 바꾸고 세 구간 테스트** — 새 채팅·이어지는 채팅·50턴 이후를 각각 확인한 뒤 공개하는가.

### 4-2. 실무 권장 예산 [종합]

원칙: "플랫폼 권장의 60~70%만 상시 프롬프트에, 나머지는 로어북·예시·첫 메시지로"(research/03 부록 B-3). 크랙 공식도 "3,000자를 무리해서 채우지 않는 편이 기억력에 유리"라고 명시한다 [공식 research/02 1.4].

| 플랫폼 | 상시 프롬프트 권장 | 첫 메시지 권장 | 예시 대화 권장 | 로어북 권장 |
|---|---|---|---|---|
| 크랙 | **1,500~2,000자** (3,000자 상한의 50~70%) | 원하는 턴당 응답 길이의 1~1.5배. 보통 400~900자 | 3개, 각 150~300자, 무드 다르게 | 20개 중 상위 3개에 핵심, 나머지는 묶기(`04-lorebook.md` 5절) |
| 케이브덕 | 설명+세계관+비밀+문체 **합산 1,400~2,000토큰** (저렴 모델 유저 고려). 고급 모델 전용 작품이면 3,500토큰 이내 | 에피소드당 500~1,500자(10,000자 상한은 쓰지 않음) | 항상 적용 2~3개 + 상황 적용 2~4개 | 항목당 150~350자, 상위 10개에 핵심 |
| 베이비챗/투킷 | **3,000~4,500자** (시스템 템플릿이 길이·형식을 관리하므로 지시 중복 금지) | 첫 상황 300~700자 + 첫 대사 200~400자 | 상세 설정 안에 2~3개(별도 칸 없음) | 항목당 200~400자, 상위 5개에 핵심 |
| 제타 | **1,500~1,800자** (2,400자 기준 70%) | 인트로 400~1,000자(장문 선호 유저층은 더 길게) | 상황 예시 2~3개 | 설정집에 세계 용어 중심 |

### 4-3. 토큰 계산 주의

- 케이브덕은 글자 수가 아니라 **토큰**으로 계산하며 "단어 위주로 작성하면 유리" [공식 research/09 D]. 제작 화면 토큰 표시(권장 5,000·8,000 초과 경고)는 [커뮤니티 나무위키] 수치다.
- 한글 1자가 몇 토큰인지는 모델별로 다르다(**미확인**). 글자 수로 짐작하지 말고 케이브덕 제작 화면의 토큰 표시, 크랙 미리보기 응답 품질로 확인한다.
- 크랙 공식: 일정 토큰 이상이면 **중간 맥락**을 잘 활용하지 못한다 [공식 research/03 8-1] → 중요한 규칙은 프롬프트 맨 앞·맨 뒤에 둔다.
- SillyTavern 공식: 첫 메시지·예시 대화는 대화가 길어지면 잘려 나가고, 설명·성격·시나리오만 영구 토큰이다 [공식 research/03 3-3] → **사실 정보는 설명에, 말투·연출은 예시와 첫 메시지에**.

## 5. 이 폴더의 공통 규칙 (CLAUDE.md 6절 요약)

- 모든 예시·작품의 등장인물은 **성인(나이 명시)**, **오리지널**. 실존 인물·타 작품 캐릭터 금지(플랫폼 공식 콜라보만 예외).
- 미성년으로 보일 수 있는 요소(교복·교실·학생회·어린 외형) 금지 — 케이브덕·크랙·베이비챗 모두 "설정상 성인이어도 미성년 간주" [공식 research/09 C-1, research/10 D, research/02 3.4].
- 크랙 세이프티/언세이프티는 **등록 후 변경 불가**, 베이비챗은 **성인→전체 되돌리기 불가** [공식] → 컨셉 단계에서 등급을 확정한다.
- 작품 본문은 마스터 카드 1개로 쓰고, 제출 시 `templates/platform-mapping.md`로 변환한다(중복 집필 금지).
