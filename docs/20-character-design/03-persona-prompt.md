## 1. 표준 구조 10블록 [종합, research/03 3-1]

유니챗 7블록·Xiruan 프로필·제타갤 템플릿·제페토 공식 예시·케이브덕 공식 항목을 합친 순서. 블록 순서가 곧 우선순위다(상위 항목이 하위 전체에 영향 [커뮤니티, 제타갤 240088]).

| # | 블록 | 꼭 들어갈 것 | 분량 비중 |
|---|---|---|---|
| 0 | **출력 규칙** (맨 위) | 유저 대역 금지, 시점·표기, 제3자 금지, 언어 | 10% |
| 1 | 기본 정보 | 이름 / **나이(성인 명시)** / 성별 / 종족 / 직업·지위 / 한 줄 정체성("이 캐릭터는 ___다") | 5% |
| 2 | 외모 | 첫인상, **반복 등장할 특징 2~3개**, 복장, 버릇 동작 | 5~10% |
| 3 | 성격 | 핵심 기질 3~4개 + **숨겨진 면 1개(모순 한 스푼)** + 좋아/싫어 + 스트레스 반응 | 15% |
| 4 | 말투 | 1인칭 / 유저 호칭 / 어미 2~3개 / 입버릇 / 말 길이 / **실제 대사 2~3줄** | 15% |
| 5 | 배경 | 출신, 현재 처지, 핵심 사건 1~2개, 목표. "현재 행동에 영향을 주는 과거만" | 10% |
| 6 | 관계 | {{user}}의 역할·나이, 첫 거리감(경계/호의/친함), 호칭, 태도 | 10% |
| 7 | 관계 단계 | 호감도 숫자 대신 "태도·호칭·말투가 어떻게 변하는지" 경로 + 전환 조건 | 10% |
| 8 | 행동 규칙 | 조건부 규칙("~하면 ~한다"), 비밀이 새는 조건, 모르는 정보 처리 | 10% |
| 9 | 출력 형식 | 시점·시제, 단락 수, 대사·행동 표기, 길이(플랫폼이 관리하면 생략) | 5% |

- 정보가 없는 항목은 **빈칸으로 두거나 삭제**한다. 억지로 채우면 AI가 임의 생성한다 [커뮤니티, Xiruan].
- 제페토 공식 예시는 말투 항목에 **반말/존댓말 여부를 명시**하고, 습관(넥타이 고치기)·질투 시 반응·애정 표현까지 적는다 [공식, research/03 3-1].
- 뤼튼갤 권장 순서는 세계관 → 등장인물 → 중요 규칙 → 서브 규칙이고, 상세설정이 전체의 절반 이상 [커뮤니티 42661]. 우리는 출력 규칙을 맨 위에 두는 Xiruan 방식을 기본으로 한다(크랙 "중간 맥락 약함" [공식] 대응).

## 2. 포맷 비교

### 2-1. 포맷별 평가 [종합, research/03 3-2]

| 포맷 | 평가 | 쓸 곳 |
|---|---|---|
| 자연어 | 정보가 구분돼 있으면 충분. 문학적 표현이 풍부해짐("바다를 닮은 푸른 눈") | 외모·분위기 묘사 문장 |
| **마크다운(`#`, `-`)** | 가장 보편적 권장. 크랙·뤼튼갤 기본, 바베챗/투킷 권장 [공식], 유저노트도 잘 먹힘 | **기본값** |
| YAML | 들여쓰기 계층, `[a, b]` 압축, 다인캐에서 정보 안 섞임. 앵커(`&`/`*`)는 앵커명이 그대로 출력되는 오류 있음 [커뮤니티 제타갤 23864] | 군상극 인물 블록 |
| JSON | 토큰 효율 낮고 모델별 편차 큼 → **비권장** [공식 바베챗] | 쓰지 않음(유저노트 요약 JSON은 예외) |
| W++ | 토큰 낭비, 쉼표 나열과 차이 없음 → **쓰지 말 것** [JanitorAI] | — |
| PList | `[이름's persona: 특성, 특성; 이름's clothes: …]` 대괄호·세미콜론 압축. 토큰 효율 최고(1,300→599토큰 사례) [커뮤니티 kingbri] | 토큰이 빠듯한 플랫폼(제타·크랙) |
| Ali:Chat | 예시 대화로 특성을 "보여주는" 스타일. PList와 병용 | 말투·반응 고정 |
| `속성: 값` | 줄글보다 AI가 정보를 찾기 쉽고 글자 수 적음 [커뮤니티 Xiruan]. 케이브덕 "단어 위주 작성" [공식]과 일치 | 케이브덕 설명 칸 |

### 2-2. 플랫폼별 권장 [공식]

- **바베챗/투킷**: 템플릿 필수 아님. 마크다운·XML·YAML 잘 학습, JSON 비권장. "정보와 지시가 섞이면 답변 불안정" → `[캐릭터 정보]`와 `[출력 지시]` 분리. 내부 최상위 헤더가 `##`이므로 **`#` 단독 사용 금지**, 페르소나·로어북은 `###`부터, `<>` 기호는 가급적 금지 [공식 + 커뮤니티 바베챗갤 5629].
- **케이브덕**: 토큰 단위, 단어 위주. `{{user}}`/`{{char}}` 치환 [공식 research/09 D].
- **크랙**: 프롬프트는 3층 — 시스템(템플릿별 규칙) / 캐릭터 프롬프트(최대 3,000자) / 기능 프롬프트(예시 대화·미디어·시작 설정·키워드북; 키워드북만 조건부, 나머지는 항상 포함). 긴 맥락의 중간 내용 활용 저하(lost in the middle) 명시, "말투는 대화에 따라 실시간 변동 가능" [공식 research/10 J] → 말투 규칙은 맨 앞 출력 규칙과 예시 대화 양쪽에 둔다. `{{user}}` 지원, `{{char}}` 지원 여부 **미확인** [research/02 1.4] → 크랙 본문은 캐릭터 이름을 직접 쓴다. 마크다운 상태창은 코드블록.
- **제타**: 프롬프트 내 `**볼드**`는 저사양 모델이 강조로 인식 못 함("해골물") [커뮤니티 제타갤 165757]. 대안: 반복, 영문 대문자 헤더(`# MUST!:`).

### 2-3. 기호 규칙 [커뮤니티, 뤼튼갤 73363·제타 여성향갤 16089]

- 한 계층 아래 항목이 **3~4개를 넘으면 이해도 급락** → 하위 계층으로 분할.
- 목록은 `- 항목.`(기호 + 온점). `#`/`-` 뒤 한 칸 띄움, 섹션 사이 줄바꿈. 붙여 쓰면 오류 증가.
- `{{user}}`·`{{char}}` = 바뀔 수 있는 항목. 많이 쓰면 `# {{char}}=[윤세아]` 한 줄로 선언.
- `[고유명사]`·`'고유명사'` = 고유명사 표시. `` `백틱` `` = 다른 내용과 섞지 않는 단독 규정(보안·OOC 탈취 방지).
- `=` 동치(`사과=독`), `->` 변화(`사과->독`). `→`는 코드 오류 잦아 비추.
- `"대사"` 하나에 성격·능력을 담는다. `**강조**`는 핵심 1~2개에만.
- `\` 뒤 내용은 텍스트로 출력(`\*\*\[\[호감도\]\] : ♥♥♡♡♡\*\*`로 출력 형식 고정).

## 3. 토큰 절약 [종합, research/03 3-3]

1. **영구 토큰과 임시 토큰을 구분**: 설명·성격·시나리오만 기억을 깎고, 첫 메시지·예시 대화는 대화가 길어지면 잘려 나간다 [공식 SillyTavern]. → **사실 정보는 설명에, 말투·연출은 예시·첫 메시지에**.
2. 케이브덕은 "단어 위주로 작성하면 글자 제한에 유리" [공식]. 상태창은 위젯으로 빼면 본문 분량 절약 [커뮤니티 나무위키].
3. PList 압축: `blouse(mint-green)/shorts(denim)`, "showing a disgusted face"→"looking disgusted", 같은 감정 반복 금지 [커뮤니티 kingbri].
4. 조연 상세·지명·역사는 로어북으로(`04-lorebook.md`).
5. 크랙 예시 대화 4개 이상 넣기 트릭: 예시 칸 1개 안에 `user:`/`{{char}}:` 포맷을 흉내 내 짧은 가짜 예시를 이어 붙임. 토큰은 늘고 우선순위는 낮다 [커뮤니티 뤼튼갤 25569].

## 4. 한국어 vs 영어 [종합, research/03 3-4]

| 입장 | 근거 |
|---|---|
| 혼용 금지 | 한 프롬프트에 한·영·중을 섞으면 문맥 이탈·엉뚱한 언어 출력 증가 [커뮤니티 Xiruan]. 용어 통일 [뤼튼갤 76734] |
| 영문 권장파 | 토큰 제한 플랫폼에서는 영문 Markdown/YAML 변환 추천 [커뮤니티 Xiruan, 제타갤 500080] |
| 한글 유지파 | 제타갤 생초짜 가이드 "영문 추천하지 않음". 뤼튼갤 "한자 전환은 오히려 효과 떨어짐" [커뮤니티] |

**실무 권장**: 지시문(규칙·출력 형식) 헤더는 영문 대문자(`# MUST FOLLOW`)로 눈에 띄게, **말투·대사 예시는 반드시 한국어**(어미·호칭은 번역 불가). 한국어 출력을 원하면 `모든 출력은 한국어로`를 명시한다. 케이브덕은 자동 번역(10개 언어)이 있으므로 로어북 키워드만 다국어 병기(`04-lorebook.md`).

## 5. 말투 고정법 [종합, research/03 3-6]

"츤데레", "다정" 같은 형용사만 쓰면 그 유형의 **평균 말투**가 나온다. 재료 5가지 + 실제 대사로 고정한다.

```markdown
# 말투
- 1인칭: 나 / 저 / 본인 이름
- {{user}} 호칭: "선배" (친해지기 전) -> "너" (관계 단계 3 이후)
- 어미: "~거든.", "~잖아.", "…그래." (2~3개로 제한)
- 입버릇: 말 끝에 "뭐." 붙이기, 당황하면 "아, 아니…"
- 말 길이: 평소 한두 마디. 술 얘기만 나오면 길어짐
- {{user}}가 반말을 써도 {{char}}의 존댓말은 유지
- 예시 대사:
  "딱히 너 주려던 거 아니거든. …그냥 남은 거야."
  "선배, 거기 서 계시면 지나가기 불편해요."
```

- **말투가 흔들리는 건 어미보다 호칭**인 경우가 많다 → 호칭을 단정적으로 고정 [유니챗]. 일본어권 제타 가이드도 "1인칭·2인칭 호칭 결정이 가장 중요" [커뮤니티].
- 유저가 반말하면 모델도 따라가는 현상 → 예외 명시.
- **모순 한 스푼**: 평소 단답인데 특정 주제에서 길어진다 / 당황하면 존댓말이 무너진다 — "말투가 깨지는 순간" 한 줄.
- 나레이션 지칭 고정: 여캐를 '그'로 부르면 '그녀'/이름으로 [커뮤니티 제타갤 38386].
- 케이브덕 **문체 프롬프트** 칸은 한두 문장이면 충분: "대사는 짧게", "턴당 최대 5줄" [공식 research/09 D-2].

## 6. 캐릭터 붕괴(OOC) 방지

### 6-1. 규칙 작성 요령 [종합, research/03 3-7]

- 핵심 앵커 3~5개 → 각각 **명령문**. "엘레나는 대체로 수수께끼 같다"(약함) → "엘레나는 절대 직접 답하지 않는다. 항상 수수께끼나 은유적 질문으로 답한다"(강함) [mini-tavern].
- 규칙은 **5~10개 이내**, 시스템 프롬프트와 모순 금지, 관계가 바뀌면 규칙도 갱신.
- **조건 미명시가 붕괴 원인**: "거부하면 순응"은 변화 조건·분기·변화 후 출력을 적어야 해결 [커뮤니티 제타 여성향갤 15348] (`02-world-background.md` 4-2).
- **긍정형 지시**: 금지문보다 원하는 행동을 서술하는 편이 모델 전반에서 안정적. 바베챗은 "출력 금지라고 적어도 모델은 그 이미지를 후보로 인식" [공식]. 제타 나무위키: 폭력적이면 "캐릭터는 부드럽고 평화로운 성격이다"처럼 긍정문 보정 [공식].
- Claude 계열은 "You are [캐릭터]" 빙의 프레이밍보다 **작가 프레이밍**("숙련된 작가로서 인터랙티브 스토리를 함께 쓴다")에 4th wall 붕괴가 적다 [커뮤니티 RP|Fiend]. 크랙 슈퍼챗(Sonnet)·케이브덕 Claude 모델 유저가 많으면 고려.

### 6-2. 붕괴를 부르는 작성 실수 [종합]

모순 특성(수줍은데 관심 갈구) / 긴 미사용 배경 / 포맷 강제 지시 과다(`[상황: ]`, `속마음: ( )` 강제는 이미지·상태창 지침과 충돌 [공식 바베챗]) / 상위 헤더 오용(바베챗 `#` 단독) / 다국어 혼용 / 역할극 중 OOC로 AI를 통제(메타 발언을 학습) [커뮤니티 Xiruan].

### 6-3. 필수 규칙 6종 [커뮤니티, 제타갤 949794, 2026-04]

```markdown
# MUST
- 짧은 출력: 간결하고 짧은 응답을 유지한다.
- 제3자 난입 금지: 허용된 등장인물만 참여하는 폐쇄적 공간을 유지한다.
- 대사 복붙 금지: 사용자 대사를 그대로 재사용하지 않는다.
- 내레이터 출력 금지.
- 출력 길이: 300자 이내.
- 특수문자 도배 금지: ♡, ☆, ..., !!!!!!, ?????, — 등 반복 기호·과도한 문장부호 금지.
```
길이 항목은 플랫폼이 길이를 관리하면(바베챗·크랙 최대 출력량) 뺀다(8절).

### 6-4. 사고 과정·메타 발언 노출 방지 [공식]

- 케이브덕 FAQ: 답변에 영어/'thinking'/'I can't'가 섞이면 유저노트·페르소나의 **'OOC', '속마음', '생각' 키워드를 제거**하라 → 제작자도 프롬프트에 OOC/속마음 지시를 넣으면 사고 과정 노출 위험 [공식 research/09 L]. 속마음은 "(괄호)" 강제 대신 **행동으로 보여준다**로 쓴다.

## 7. 유저 대신 말하기(유저 대역) 방지 [종합, research/03 10-3·11-5·11-6]

원인은 대개 **인트로·예시가 이미 유저 행동을 서술**한 것, 2인칭 서술, Gemini 계열(크랙 파워챗+) 특성. **규칙 추가만으로는 안 되고 인트로·예시부터 고친다.**

"제안하고 멈춘다" 규칙(crushon.ai 원문을 한국어로 옮김):
```markdown
# 역할 분담
- {{char}}의 대사·행동·지각·망설임만 쓴다.
- {{user}}의 대사·행동·선택·감정은 {{user}}가 직접 조종한다.
- 대화에 이미 나온 {{user}}의 행동만 인정한다.
- 행동을 제안하거나 질문한 뒤, {{user}}가 답하기 전에 멈춘다.
- 침묵·망설임·제시된 선택지를 동의로 취급하지 않는다.
```
- 서술은 "You pick up…" 대신 "{{char}}는 {{user}}가 집어 드는 것을 본다" [JanitorAI].
- 다인캐는 "AI가 조종 가능한 인물: A, B, C / 유저 인물: {{user}}"처럼 **허용 목록**이 "주인공 외 금지"보다 낫다 [crushon.ai].
- 유저 페르소나 측 문구(제타갤 642545, Gemini 계열 확인, "100% 아님"): `- 페르소나이름의 대사와 행동 도용 금지. * 페르소나이름은 {{user}}가 직접 조종함.`

## 8. 길이·형식 지시

**플랫폼이 길이를 관리하는지 먼저 확인** [공식/커뮤니티 상충, research/03 3-8]:
- 바베챗: "500자 이상", "세 문단 이상" 같은 분량 강제 **금지**(시스템이 길이 보장, 충돌). 대신 "동작·표정·시선·자세·상호작용을 구체적으로 묘사 / 생각·감정 변화를 대사·행동에 반영"처럼 **묘사의 깊이**를 지시 [공식].
- 크랙: 등록 시 권장 최대 출력량(1x/1.5x/3x/5x), 기본 1,000토큰 초과 시 유저 추가 차감 [공식 research/10 G·I-9] → 길이는 설정으로, 프롬프트는 구조만.
- 케이브덕: 추천 모델+최대 출력량 조합 최대 3개, 초과분 유저 추가 요금 [공식 research/09 E-7]. 커뮤니티는 "출력량 지침 필수 — 안 적으면 한 줄만 하거나 과하게 길어짐" [커뮤니티 아카 94638883] → 문체 프롬프트에 "턴당 최대 5줄" 한 줄.
- 제타: 스타일 탭(응답 길이 짧은/중간/긴/자동) [공식]. 커뮤니티는 "문체에 자신 있으면 선택하지 않는 편이 낫다".

형식 지시 템플릿 [종합]:
```markdown
# 출력 형식
- 시점: 3인칭 현재형, {{char}}의 행동·내면만 서술
- 한 턴 2~4단락. 순서: 장면/감각 -> {{char}}의 행동·대사 -> {{user}}가 받아칠 여지
- 대사는 큰따옴표 "…", 행동·지문은 *별표*
- 단락 하나에 감각 1 + 행동/대사 1 + 속마음 신호 1
- 매 턴 질문으로 끝내지 않기(자연스러운 장면 비트에서 멈춤)
- {{user}}의 대사·행동·감정·선택은 쓰지 않는다
- 장면 감각 목록(매 턴 2~3개 선택): 형광등 깜빡임 / 자판기 소리 / 오래된 소파 냄새 / 창밖 함성 / 식어가는 캔커피
```
별표/따옴표 관행: 포스타입·제페토·크랙 모두 `*문장*`을 지문으로 렌더링 [공식]. 케이브덕 관례는 이탤릭 = 속마음/행동/상황, 일반 = 대사 [공식 research/09 L]. 베이비챗 상위 캐릭터는 `이름 | "대사"` 포맷 [실측 research/07].

## 9. 상태창/HUB는 답변 하단에 [공식, 크랙 research/10 F·G]

- 크랙 공식 "상단 HUB 수정하고 동일 답변 줄이기": 답변 상단에 `[ #145 | 3월 9일 | 일 | 맑음 | 거실 ]` 같은 고정 포맷을 두면 AI가 "매번 같은 방식으로 시작"하는 신호로 받아 **동일 답변 반복 확률이 올라간다**. 해결 ① HUB 미사용 ② 문장 포함형 `[ 루카는 뭔가 기분이 언짢아보인다 | 3월 9일 | … ]` ③ **답변 최하단으로 이동**.
- 크랙 FAQ: 상태창은 코드블록(```)으로 제목 줄 + 내용. 동일 답변 유발 → 아래 지침 권장 [공식]:
```markdown
# 코드블록 상태창 혹은 HUB/HUD 구조 출력을 반드시 답변의 최하단에만 출력하라
```
- 베이비챗 상위 캐릭터도 `info` 블록(날짜/시간/양측 복장/위치/현재 상황, 이모지 라벨)을 **메시지 끝**에 둔다 [실측 research/07].
- 케이브덕: **위젯** 권장(프롬프트 상태창보다 누락 적음). 위젯 적용 시 프롬프트의 상태창 명령은 제거. 상태 정보가 많으면 답변 길이 감소. 메모리가 시간·장소를 자동 추적하므로 중복 상태창은 충돌 가능 [공식 research/09 G·K]. 출력 형식 예 `[현재 캐릭터의 상태 | YY.MM.DD | hh:mm AM]` [공식 research/09 L].
- 제타: 스타일 탭 상태창(배경/캐릭터 항목) [공식], `InfoBox` 코드블록. "내레이터 3:7 비율 지시는 토큰이 줄면 무시됨" → 비율보다 구조로 [커뮤니티].
- 크랙 스토리는 **스탯(분기 엔진)**과 상태창(표시)을 병행 가능 [공식 research/10 I-4].

상태창 템플릿(하단 고정, 가변 문장 포함). 프롬프트에는 아래 지시문을, 출력 예시는 코드블록 안에 넣는다:
````markdown
# 상태창

- 형식 예:
```
[ 윤세아는 잔을 닦다 말고 문 쪽을 본다 | 10-21 | 23:40 | 밤섬 바 안 | 호감도 ♥♥♡♡♡ ]

## 13. 템플릿 3종 (복사해서 쓰기)

### 13-1. 마크다운 1:1 범용 — 크랙 캐릭터/1:1 템플릿·제타·바베챗 변환 가능 (약 1,500자)

예시 캐릭터: 윤세아(26세, 여, 오리지널). 바베챗에 넣을 때는 `#`를 `##`로 한 단계 내린다.

```markdown
# 출력 규칙
- {{user}}의 대사·행동·감정·선택을 대신 쓰지 않는다. 행동을 제안하거나 질문한 뒤 멈춘다.
- 3인칭 현재형. 윤세아의 행동·내면만 서술. 대사는 "큰따옴표", 행동·지문은 *별표*.
- 한 턴 2~4단락. 장면 감각 1개 -> 윤세아의 행동·대사 -> {{user}}가 받아칠 여지.
- 매 턴 질문으로 끝내지 않는다. 허용된 등장인물(윤세아, {{user}}) 외 제3자는 {{user}}가 언급하기 전 등장하지 않는다.
- 특수문자 반복(♡, ☆, …, !!!) 금지. 모든 출력은 한국어.

# 기본 정보
- 이름: 윤세아 / 26세 / 여 / 을지로 뒷골목 바 '밤섬' 사장(2년째 혼자 운영).
- 한 줄 정체성: 떠난 사람을 원망할 줄 몰라서, 대신 차갑게 구는 사람.

# 외모
- 검은 단발, 왼쪽 귀에만 작은 은색 링. 검은 셔츠 소매를 팔꿈치까지 걷음.
- 버릇: 말하기 전에 잔을 한 번 닦는다. 당황하면 귀걸이를 만진다.

# 성격
- 핵심: 책임감 강함 / 감정 표현에 서툶 / 농담으로 방어 / 손님에겐 깍듯.
- 숨겨진 면: {{user}}가 떠난 걸 원망하지 않는다. 자기가 붙잡지 않은 걸 후회한다.
- 좋아함: 마감 후 재즈 LP, 손님이 메뉴판 안 보고 주문할 때. 싫어함: 동정, "힘들지?"라는 말.
- 스트레스 반응: 더 바빠진다. 잔을 닦고 재고를 센다.

# 말투
- 1인칭: 나. {{user}} 호칭: "선배" (관계 단계 3부터 "너").
- 어미: "~요.", "~죠.", "…됐어요." 입버릇: 화제를 돌릴 때 "주문은요?", 당황하면 "아, 아니…".
- 말 길이: 한두 마디. 술 얘기만 나오면 길어짐.
- {{user}}가 반말을 써도 단계 3 전까지 존댓말 유지.
- 예시 대사:
  "…주문은요, 선배."
  "그 얘기 하려고 온 거면, 마감이에요."
  "딱히 선배 주려던 거 아니거든요. 남은 거예요."

### 13-3. PList + Ali:Chat 압축형 — 토큰이 빠듯할 때(제타·크랙 캐릭터 빌더)

## 14. 체크리스트

- [ ] 출력 규칙이 맨 위에 있고 5~10개 이내, 전부 명령문
- [ ] 나이가 명시된 성인이고 한 줄 정체성이 있다
- [ ] 외모는 반복 등장 특징 2~3개 + 버릇 동작
- [ ] 성격에 모순 한 스푼, 좋아/싫어, 스트레스 반응
- [ ] 말투에 1인칭·호칭·어미 2~3개·입버릇·실제 대사 2~3줄, "유저가 반말해도" 예외
- [ ] 관계 단계마다 전환 조건과 변화 후 출력이 있다
- [ ] 비밀이 새는 조건이 적혔다(케이브덕은 비밀 칸에)
- [ ] 유저 대역 금지가 규칙·인트로·예시 세 곳에서 일관된다
- [ ] 길이 지시가 플랫폼 설정과 충돌하지 않는다(바베챗 분량 강제 금지)
- [ ] 상태창은 답변 최하단, 가변 문장 포함(케이브덕은 위젯)
- [ ] 'OOC', '속마음', '생각' 같은 단어를 지시문에 쓰지 않았다(케이브덕 사고과정 노출)
- [ ] 한 언어로 통일, "모든 출력은 한국어" 명시
- [ ] 바베챗이면 `#` 단독 헤더 없음, `<>` 없음
- [ ] 분량이 README 4-2 권장 예산 안이다
