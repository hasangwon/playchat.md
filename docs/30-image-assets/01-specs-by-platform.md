## 1. 크랙 (crack.wrtn.ai)

크랙은 **캐릭터 빌더(5단계)**와 **스토리 빌더(9단계)**가 다르고 이미지 규격도 다르다. 어느 빌더에 올리는지 먼저 확인.

### 1-1. 사용처와 규격

| 사용처 | 빌더 | 형식·용량 | 비율·크기 | 개수 | 근거 |
|---|---|---|---|---|---|
| 프로필 사진(필수) | 캐릭터 | PNG/JPG/WebP, **5MB 이하**, 업로드 시 AI 사전 검열 | 권장 px·비율 **미확인**. 내장 생성기 비율 안내가 "정방형=프로필용" [공식 research/10 K] → **1:1로 준비** [추정] | 1 | [공식] research/10 H |
| 프로필 사진(필수) | 스토리 | JPEG/JPG/PNG, **5MB 이하**, AI 사전 검열 | **썸네일 2:3 권장**, 1:1은 상하 여백 블러 처리 | 1 | [공식] research/10 I-1 |
| 상황 이미지(고급 기능) | 캐릭터 | 라이브러리/내장 생성 연동 | **정방형 기준**, 세로로 긴 이미지 비권장 | **최대 50개**, 모든 이미지에 상황 묘사 입력 필수 | [공식] research/10 H |
| 미디어(상황 이미지) | 스토리 | jpeg/jpg/png/webp/**gif**, 파일당 **5MB** | 정방형 기준, 세로 긴 이미지 비권장 | 신버전: 1회 업로드 **1,000장**, 작품 전체 **1,600장** / 구버전: 시작설정별 50장 | [공식] research/10 I-5 |
| 엔딩 이미지(엔딩 카드) | 스토리 | 5MB | **1,005×1,490px** 카드 사이즈 | 엔딩 수만큼(등급 N/R/SR/SSR, 엔딩 수에 따라 상위 등급 개수 제한) | [공식] research/10 I-8 |
| 상태창 이미지 배너 | 공통 | — | — | — | [공식] research/04 §1-1 (상세 미확인) |

- 엔딩 등급 상한: 엔딩 ≤2개 N/R만, 3~5개 SR 1, 6~8개 SR 2·SSR 1, 9개 이상 SR 2·SSR 2. 엔딩 이름 20자. 조건은 턴 수(최소 10턴, 5턴마다 검사)+스탯 규칙. [공식] research/10 I-8
- GIF 썸네일이 가능하다는 이용자 보고 [커뮤니티] research/02 1.5 — 프로필 형식 목록(PNG/JPG/WebP)에는 없으므로 **미확인**.

### 1-2. 삽입·호출 문법

**구버전 — 직접 삽입** [공식] research/10 G·I-3·I-5
```
{{img::이미지 이름}}
```
- 미디어 단계에서 이미지를 등록한 뒤, 위 문법을 **프롤로그(첫 인사말)·예시 대화·캐릭터 설정**에 넣는다.
- **표기 주의**: 「프롬프트의 이해」 공식 문서는 `{{img: 이미지이름}}`(콜론 1개+공백), FAQ·스토리 튜토리얼은 `{{img::이미지 이름}}`(콜론 2개) — 둘 다 공식 문서에 등장하며 어느 쪽이 실제 동작하는지는 **빌더에서 실측 필요** [공식] research/10 J·G·I-3. 실무: 빌더 우측 채팅 미리보기에서 이미지가 렌더링되는 표기를 쓰고, 한 작품 안에서는 한 가지 표기만 사용한다.
- 이미지가 대사와 겹쳐 보이면 상황 묘사 태그(`**...**`) **바깥·별도 줄**에 둔다.
```
**창밖으로 도시의 불빛이 번진다.**

{{img::하린_창가}}

하린 | "늦었네. 커피는 식었어."
```

**신버전 — 배치표 자동 호출** [공식] research/10 I-5, research/04 §1-1
1. 파일명을 `분류_상황` 형식으로 지어 올린다 → 자동 분류. 예: `하린_미소.webp`, `하린_분노.webp`, `배경_사무실밤.webp`, `사물_반지.webp`
2. 이미지별 세부 정보: **해금 힌트**(유저에게 보임, 이미지 보관함 수집 요소), **메모**(AI 호출에 영향 없음).
3. **배치표**(분류 × 상황 2축)에 배치하면 플레이 중 AI가 상황에 맞춰 자동 호출. 분류에는 인물 외 **배경·사물**도 가능.
4. 호출 트리거(키워드 매칭 규칙·상황명과 프롬프트의 관계)는 공식 문서에 없음 → **미확인**. 플레이 테스트로 확인.
- 파일명 안에 언더스코어를 2개 이상 쓰면 분류가 어떻게 되는지 **미확인** → 분류와 상황 사이에만 `_`를 쓰고, 상황 내부 구분은 붙여쓰기 또는 하이픈(`하린_미소-수줍음`)으로 한다 [추정].

**이미지 보관함·해금** [공식] research/04 §1-1: 유저가 플레이 중 이미지를 해금해 갤러리에 모은다. 해금 힌트를 "수집 요소"로 설계하면 재방문 동기가 된다 [커뮤니티] research/04 §6-1.

### 1-3. 내장 이미지 생성 [공식] research/10 K, research/04 §1-1

| 항목 | 내용 |
|---|---|
| 이미지 생성 | 프롬프트 **최대 1,000자**(영어 권장, 마법봉 '프롬프트 헬퍼'가 한글→영어 변환) → 스타일 **8종** → 비율 **5종**(정방형=프로필용, 가로형, 세로형 등) → 개수 **최대 4장** → **1장당 95크래커**(실패 시 미차감) |

| 빌더 연동 | 프로필 단계 '생성' 버튼으로 바로 생성, '업로드'로 라이브러리·좋아요 이미지를 직접 등록. 미디어(상황 이미지) 탭에서도 동일 |

### 1-4. 이미지 정책 요약 [공식] research/10 D, research/04 §1-1 (운영정책 2026-06-30 시행)

- **적용 범위**: 이름·소개·설정·프롬프트·프로필 이미지·상황별 이미지 전부. 사전 심사 없음, **사후 검토**로 사전 안내 없이 등급 전환·비공개·대화 제한.
- **프로필 이미지(세이프티·언세이프티 공통, 가장 보수적)**: 속옷·비치는 옷·민감 부위 강조, 과도한 폭력·**혈흔**, 나체·성행위 연상 포즈·성적 접촉, 이미지 내 비속어·성적 은어, 실사/실존 인물 유사 — 전부 금지. 2025-08 "프로필 이미지 규정 강화"는 기존 캐릭터에도 소급. 2025-10-08 "대중 웹툰 플랫폼 수준" 썸네일 기준 강화 시 유예 없이 차단 사례 [커뮤니티] research/05.
- **상황 이미지 – 세이프티**: 비침·젖음·찢김 의상, 성적 도구, 성행위 연상, 신체 훼손·과도한 혈흔 금지. 운동·수영복·전투·예술/교육 목적의 불가피한 노출은 민감 부위 제외 제한적 허용.
- **상황 이미지 – 언세이프티**: 성기·항문·음모·유두·유륜 직접 노출 및 **윤곽** 금지(불투명 물체/박스로 가림), 체액·배설물 성적 활용 금지, **GIF/WebP 움직이는 이미지로 성행위 묘사 금지**, 성범죄·비동의 금지. research/02 1.6에는 "블러"도 언급되나 research/10·04 원문은 불투명 가림만 → 블러는 쓰지 않는다(**미확인**).
- **미성년 외형**: 나이 설정과 무관하게 앳된 얼굴·미성숙 체형·교복·학교/학원 배경 등을 종합해 "명백히 미성년"이면 미성년으로 간주. 성적 대상화는 경고 없이 최고 제재.
- **실존 인물·저작권**: 타인 얼굴·신원 금지, 딥페이크 금지. 2차 창작은 원작자 가이드라인 준수 + **세이프티 등급으로만**(장르 '2차창작' 선택, 언세이프티 불가). **외부 이미지 활용 위반은 경고 없이 최고 제재**.
- AI 생성 이미지 자체를 금지하는 조항은 없음.
- 규정 하위 문서(프로필 이미지 / 상체 이미지 / 혈흔 / 수영복 / 세부 기준)가 고객센터에 있으나 URL **미확인**. 커뮤니티 정리본: https://gall.dcinside.com/mgallery/board/view/?id=wrtnai&no=565785 (2025-07-04) [커뮤니티].

### 2-2. 앨범 키워드 문법 [공식] research/09 D-3, research/04 §1-2

- 업로드하면 **키워드가 자동 부여**되고, 대화 맥락에 맞는 키워드의 이미지가 자동 출력된다. 키워드가 파일명에서 오는지, 업로드 후 편집하는지는 **미확인** → 파일명을 키워드와 같게 지어 두면 어느 쪽이든 안전.
- 키워드는 **간결·명확·다양하게**. 같은 상황 여러 장이면 `smile1, smile2`가 아니라 **`smile`로 통일** → 그중 1장 랜덤 출력.
- `random`처럼 상황을 특정하지 않는 키워드는 오동작.
- 커뮤니티 일부 글의 `smile_1` 번호 방식은 구버전/상충 → **공식 우선** [커뮤니티] research/04 §6-1.

권장 키워드 세트(영문, 표정 9종 + 상황):
```
neutral, smile, laugh, blush, angry, sad, surprised, smug, sleepy
intro, hug, kiss, date, fight, rain, night, home, office
```
