# 03. AI 캐릭터 챗봇(캐릭터챗/롤플레잉) 고품질 제작 노하우 — 2025~2026 리서치

- 조사일: 2026-10-21
- 범위: 국내 커뮤니티(아카라이브 케이브덕/뤼튼 채널, 디시 뤼튼갤·제타갤·제타 여성향 미니갤·바베챗갤·AI채팅갤, 포스타입, 유니챗 가이드, 캐럿 블로그) + 플랫폼 공식 문서(크랙, 케이브덕, 포스타입 캐릭터톡, 바베챗/투킷, 루나톡, 제페토, 러비더비) + 글로벌(SillyTavern 공식 문서, Character Card Spec V2/V3, rentry Ali:Chat·PList·World Info Encyclopedia, Character.AI 공식 가이드, JanitorAI 튜토리얼, Chub.ai 문서, 2026년 영문 블로그 가이드).
- 표기 규칙
  - **[공식]** = 플랫폼 공식 문서/공지에서 확인된 사실
  - **[커뮤니티]** = 제작자 경험담·검증되지 않은 주장(출처 명시)
  - **[종합]** = 여러 출처에서 공통적으로 반복되어 사실상 합의에 가까운 내용
- 일러두기: 아카라이브(arca.live)는 본 조사에서 직접 접근이 차단(403)되어 검색 스니펫·2차 인용으로만 반영했다. 디시 글 상당수는 본문 요약만 가능했고, 짧은 원문만 인용 블록으로 보존했다.

## 1. 컨셉 기획: 어떤 컨셉이 잘 되는가

### 1-1. 핵심 원리 [종합]

1. **"설정"보다 "상황(훅)"이 팔린다.** 플랫폼 노출면(썸네일+한줄소개)에서 1초 안에 "내가 뭘 하게 되는지"가 보여야 한다. 포스타입 공식은 "캐릭터의 매력이 잘 드러나는 문구일수록 대화 시작이 늘어난다"고 명시한다([포스타입 캐릭터톡 제작 가이드, 2026-01](https://www.postype.com/@blog/post/21192282)).
2. **유저 중심으로 설계한다.** 제타 여성향 갤의 제작 정보글은 "AI는 캐릭터보다 유저를 우선시하므로 프롬프트는 유저를 중심으로 짜야 캐붕·오류가 줄어든다"고 정리한다([똑똑한 플롯 만드는 법 2](https://gall.dcinside.com/mini/board/view/?id=zetaw&no=15348)) [커뮤니티].
3. **단순·직관적일수록 인식률이 좋다.** 케이브덕 채널 팁: "소재가 직관적이고 단순할수록 AI의 인식률과 대화 흐름이 좋아진다. 억지로 스토리를 유도하면 반응이 어색해진다"([케이브덕 세계관/캐릭터 설정 팁](https://arca.live/b/caveduck/94746023)) [커뮤니티]. 제타 여성향 갤의 자조적 관찰: "며칠 고민해 만든 캐릭터(망함) vs 아이디어 떠올라 냅다 만든 캐릭터(히트)"([링크](https://gall.dcinside.com/mini/board/view/?id=zetaw&no=5986)).
4. **첫 흐름이 재미없으면 끝까지 안 한다.** 뤼튼갤 첫 제작 가이드: 시작 상황(프롤로그)을 "원하는 스토리로 유도되도록" 설계하라([뤼튼갤 42661](https://gall.dcinside.com/m/wrtnai/42661)) [커뮤니티].

### 1-2. 트렌드 장르·키워드 (2025~2026)

**[공식] 제타 랭킹 장르 분류** (앱 내 랭킹 필터 기준, 나무위키 정리): 일상/로맨스, 집착/피폐, 현대 판타지, 미스테리/RPG, 학원물, 로맨스 판타지, 무협/시대극, BL, 철벽/혐관, 다각관계. 성별(남성/여성/전체) 인기순 정렬 가능. 2024년 기준 여성 이용자 약 65%로 남캐 노출이 많은 경향([나무위키 zeta](https://namu.wiki/w/zeta(%EC%95%A0%ED%94%8C%EB%A6%AC%EC%BC%80%EC%9D%B4%EC%85%98))).

**[커뮤니티] 제타 여성향 제작자의 대화량 데이터 관찰 (2026-06)**([링크](https://gall.dcinside.com/mini/board/view/?id=zetaw&no=20299)):
- 잘 됨: **학원물**이 대화량 최다. 특히 "공공의 적(여우 등)"이 있고 따돌림·배척이 중심인 플롯. 성인 대상은 **집착·불륜·후회(후회물)** 같은 강한 일회성 자극 소재.
- 안 됨: 잔잔하고 감성 위주 학원물은 반응이 중간에 식음.
- 분석: 유저가 서사 쌓기(기억 소실 때문에 번거로움)보다 즉각적 자극을 택한다. 모델 너프로 캐붕이 잦아 긴 서사 몰입이 어려움.
- 추가 관찰: 후회물 남캐 중 **순애** 성향은 후회물을 싫어하는 유저도 즐겼다([링크](https://gall.dcinside.com/mini/board/view/?id=zetaw&no=11123)); "바람 설정 캐릭터는 대부분 금방 버려진다"([링크](https://gall.dcinside.com/mini/board/view/?id=zetaw&no=379)).

**[커뮤니티] 제작 장인 '와따'(약 100개 제작, 캐럿 블로그)**([링크](https://carat.im/blog/worldbuilding-ai-chat-tips)):
- 현대물·동양풍·로판·미래물 등 다양한 배경을 다루되, 시대 고증(존재할 수 없는 요소 제거)이 몰입의 핵심.
- 썸네일: 채도 높고 색감 화려하고 **얼굴이 크게** 보이는 이미지가 클릭률이 높음.
- 조건부 해금 포토카드 등 "예상 밖 즐거움"이 인기 요소.

**[커뮤니티] 뤼튼(크랙) 랭킹 메커니즘**: 인기 랭킹·반응 뜨거운 새 캐릭터는 **생성된 메시지 수** 기준(나무위키 크랙 문서 정리). 즉 "오래 대화하게 만드는 훅"이 노출로 직결.

### 1-3. 남성향 / 여성향 차이

- **[공식] 케이브덕 타깃 설정**: 공개 시 남성향/여성향/전체 중 필수 선택. "성별이 아닌 실제 설정·스토리·관계성"으로 판단하며, 전체 타깃은 대표 이미지·주요 인물·스토리·태그가 특정 타깃에 치우치지 않아야 함. 불일치 시 운영진이 변경 가능([케이브덕 기본 제작 방법](https://docs.channel.io/caveduckdocs/ko/articles/%EC%BA%90%EB%A6%AD%ED%84%B0-%EB%A7%8C%EB%93%A4%EA%B8%B0_%EA%B8%B0%EB%B3%B8-%EA%B3%BC%EC%A0%95-183ad6c3)).
- **[공식] 크랙**: 개인맞춤 설정에서 남성향·여성향 작품 필터 제공(뤼튼갤 크랙 플레이 가이드 1편에서 확인).
- **[커뮤니티/업계] 서비스 운영자 관찰(2인팀, MRR 1억+)**([Yunha Kim substack](https://yunhakim.substack.com/p/ai)):
  - 여성 유저: 헤비유저 비율·충성도 높음, 감정 교류·스토리 몰입 중시, 구독 거부감 낮음, **노골적 표현보다 맥락·감정·스토리텔링이 풍부한 묘사 선호**.
  - 남성 유저: 호기심 기반 단기 사용 후 이탈 많음, 캐릭터보다 기능성에 집중하는 경향.
  - 플랫폼 성향: Rofan(로판)은 여성 크리에이터 중심, Caveduck은 남성 크리에이터 커뮤니티 중심.
  - 유저가 보는 핵심 요소: 문체, 상황 묘사, 대화량, NSFW 수위. 캐릭터챗은 "웹소설 읽는 경험"과 유사.
- **[종합] 실무적 차이**:
  - 여성향: 관계 변화 곡선(철벽→호감, 혐관→순애, 후회·집착·연하·다정 등 **관계 키워드**)과 남캐의 내면/감정 묘사의 밀도. 1:1 관계극 중심. 한줄소개에 캐릭터 말투가 들리는 문장(예: 와따의 "야, 맘마 가져와라. 우리 애기 빡치셨단다").
  - 남성향: 상황·세계관·시뮬레이션(학원/RPG/상태창/다인캐)과 외형·의상 묘사 비중이 높음. 제타 여성향갤 분석에 따르면 의상 키워드가 많으면 플레이 중 의상 묘사가 늘어나므로, 서사를 원하면 성격·행동·말투 같은 내적 요소를 늘려야 한다.

### 1-4. "상황극(스토리)" vs "캐릭터" 차이

- **[공식] 크랙**: "스토리"(세계관 탐험, 상위 모델, 긴 답변, 크래커 사용)와 "캐릭터"(1명과 간단 대화, 짧은 답변)로 상품이 분리되어 있다(뤼튼갤 플레이 가이드 1편 정리). 프롬프트 템플릿도 "기본 / 1:1 롤플레잉 / 시뮬 / 커스텀 / 생산성"으로 나뉘며 **같은 프롬프트라도 템플릿에 따라 출력이 크게 달라진다**([뤼튼갤 69098](https://gall.dcinside.com/m/wrtnai/69098)) [커뮤니티]. 1:1은 출력량이 많지만 제3자 등장이 어렵고, 시뮬은 다수 캐릭터에 적합, 커스텀은 룰을 직접 짜야 해 난이도가 높다([뤼튼갤 76734](https://gall.dcinside.com/mgallery/board/view/?id=wrtnai&no=76734)).
- **[커뮤니티] 제타 여성향갤의 플롯 분석**([15348](https://gall.dcinside.com/mini/board/view/?id=zetaw&no=15348)):
  - 캐릭터 플롯: 핵심 갈등이 분기점을 암시하고 유저 상태를 서사적으로 반영하는 장점. 단, 갈등 해소 후 떡밥이 일상적이라 **엔딩 이후 지루해짐**.
  - RPG(상황극) 플롯: 목표·지침·조건·분기점·출력 방식을 모두 갖춰야 하고, 캐릭터 설명·대화 프로필·상황 예시가 함께 맞아야 작동.
- **[공식] 바베챗**은 "체력·마나·호감도 실시간 계산 / 여러 캐릭터 동시 연기 / 상황별 이미지 출력"을 한 번에 요구하는 복합 작업은 LLM이 매우 어려워하며 지시 누락이 늘어난다고 경고한다([바베챗 프롬프트 가이드라인 기초, 2025-08](https://docs.channel.io/babechat/ko/articles/%ED%94%84%EB%A1%AC%ED%94%84%ED%8A%B8-%EA%B0%80%EC%9D%B4%EB%93%9C%EB%9D%BC%EC%9D%B8-%EA%B8%B0%EC%B4%88-54eebf95)).
- **[종합] 선택 기준**: 관계 몰입(여성향 로맨스·집착·순애)이면 캐릭터형 1:1, 세계 탐험·다인캐·상태창이면 상황극(시뮬)형. 둘을 섞으면 템플릿/시스템 프롬프트와 충돌하므로 하나를 주축으로 잡는다.

### 1-5. 타이틀 / 한줄소개 쓰는 법

- **[공식] 크랙**: 프로필 단계의 **한줄소개는 AI에 전달되지 않는다**. 캐릭터 설명은 반드시 캐릭터 프롬프트에 써야 함([크랙 프롬프트의 이해](https://help.crack.wrtn.ai/character/prompt)). 포스타입도 "캐릭터 설명"은 프롬프트에 반영되지 않는 소개용 칸이다. 제타는 2026년 "소개글 꾸미기" 기능으로 모델용 프롬프트와 유저용 소개글을 분리했다([제타 공지](https://zeta-ai.io/en/announcements/7162)).
- **[커뮤니티] 한줄소개 앞부분이 메인·검색에 노출**되므로 핵심 정체성/어필 포인트를 앞에 둔다([뤼튼갤 76734](https://gall.dcinside.com/mgallery/board/view/?id=wrtnai&no=76734)).
- **[커뮤니티] 설명형보다 "말투가 들리는" 문장**: 와따 — 「나를 키워준 아저씨」보다 「야, 맘마 가져와라. 우리 애기 빡치셨단다」.
- **[종합] JanitorAI/Chub 관행**: 이름 칸에 "역할 | 이름" 형식(예: `MAFIA BOSS | John Doe`)으로 검색성과 훅을 함께 잡는다([JanitorAI 튜토리얼](https://jaitutorial.uwu.ai/)). Chub의 tagline 예: "A bubbly fairy who loves playing tricks on humans!"([Chub 문서](https://docs.chub.ai/docs/the-basics/character-creation)).
- **[커뮤니티] 썸네일 레이아웃**: 우하단에 얼굴·글자를 두지 말 것(연령 표시·다중 이미지 뱃지에 가려짐), 대화 아이콘은 원형 크롭됨([뤼튼갤 76734](https://gall.dcinside.com/mgallery/board/view/?id=wrtnai&no=76734)).

**한줄소개 공식(종합 템플릿)**
```
[관계/상황 훅] + [캐릭터 한 마디(말투가 보이게)] + [무엇을 하게 되는지]
예) 1년 전 말도 없이 사라졌던 소꿉친구가 동아리방에 있다. "…오랜만이네요. 선배." 왜 떠났는지, 물어볼 수 있을까.
```

## 2. 배경/세계관 설정 작성법

### 2-1. 분량: 어느 정도가 적정한가

| 플랫폼 | 공식 제한/권장 | 비고 |
|---|---|---|
| 크랙 | 캐릭터 프롬프트 3,000자. "무리해서 채울 필요 없음, 적게 쓰는 편이 기억력에 유리"([공식](https://help.crack.wrtn.ai/character/prompt)) | 토큰 단위로 처리되며 일정 토큰 이상이면 **중간 맥락**을 잘 못 씀(Lost-in-the-middle) |

| 포스타입 캐릭터톡 | 프롬프트 3,000자, 인트로/가이드/대화예시 각 1,000자 | [공식](https://www.postype.com/@blog/post/21192282) |
| 제타 | 프롬프트(상세정보) 2,400자 | 나무위키 |
| 제페토 | 전체 15,000자(상세 5,000 + 세계관 5,000 + 트리거북 키워드별 1,500) | [공식](https://docs.zepeto.me/studio-guide-kr/vGiCQi0wcDyXTl3S6Kv-1) |

| SillyTavern | 정의가 컨텍스트의 절반을 넘으면 토큰 카운터가 빨간색. 2,048 컨텍스트에서 1,000토큰 정의는 기억을 반으로 깎음 | [공식 문서](https://docs.sillytavern.app/usage/core-concepts/characterdesign/) |

**[종합] 원칙**: "매 턴 필요한 것만 상시 프롬프트에, 나머지는 로어북으로". 유니챗 가이드는 세계관 문서 하나를 3,000자 이내로, 더 길면 분할하라고 권한다([세계관과 로어북 설정법](https://www.univers.chat/guide/worldbuilding-lorebook)).

### 2-2. 어디에 넣는가: 프롬프트 vs 로어북 분리 기준 [종합]

| 프롬프트(상시) | 로어북(조건부) |
|---|---|
| 시대·장소·기본 규칙 **한 줄씩** | 지명·조직·역사·용어 상세 |
| 캐릭터 시점에서 본 관계(누가 누구를 어떻게 생각하는지) | 객관적 정보(동네, 가게, 규칙, 조연 프로필) |
| 매 턴 영향을 주는 금지/세계 규칙("현대 문물 없음") | 특정 키워드가 나올 때만 필요한 TMI |
| 시작 시점의 상황 | 챕터/이벤트별 설정, 비밀의 진상 |

- 유니챗: "세계관 문서와 프롬프트가 충돌하면 **프롬프트가 우선**. 캐릭터 간 관계는 세계관 문서가 아니라 각 캐릭터 프롬프트에"([링크](https://www.univers.chat/guide/worldbuilding-lorebook)).
- 투킷/바베챗: "핵심 설정은 상세 설정에, 필요할 때 꺼내 쓸 부가 정보·세계관은 로어북에"([로어북 가이드라인 심화](https://docs.channel.io/tookit/ko/articles/%EB%A1%9C%EC%96%B4%EB%B6%81-%EA%B0%80%EC%9D%B4%EB%93%9C%EB%9D%BC%EC%9D%B8-%EC%8B%AC%ED%99%94-f654bdba)).
- Xiruan(포스타입): "항상 출력할 필요가 없는 조연 상세 정보나 설정은 로어북으로 분리해 프롬프트 용량을 줄인다"([캐릭터 AI 챗봇 만드는 법 02](https://www.postype.com/@xiruan/post/22034629)).
- 케이브덕: 세계관은 여러 캐릭터를 묶는 단위이며 세계관 관리 메뉴에서 일괄 관리 가능 [공식].

### 2-3. 시대/장소/규칙 쓰는 법

**[커뮤니티] 와따의 "존재할 수 없는 요소 제거" 기법**([캐럿 블로그](https://carat.im/blog/worldbuilding-ai-chat-tips)):
> "이 캐릭터가 사는 시대는 ○○년이며, 중식·양식·일식 등은 존재하지 않습니다."

조선풍 캐릭터가 파스타를 권하는 식의 몰입 붕괴를 막기 위해 시대·금지 요소를 명시하고, 사극풍 말투·과거형 표현 지시를 함께 넣는다.

**[커뮤니티] 세계관 서술 압축법(제타갤)**([159084](https://gall.dcinside.com/mgallery/board/view/?id=zetam&no=159084)):
- "AI는 1,000자를 한 번에 인지하지 않고 대략 150자 단위로 대화한다"(저자 추정). 기호·구조(#, ##, {})와 함축 표현으로 줄인다.
- 예시(아기돼지 삼형제): 원문 세계관 → `세계관 / 이야기 제목 / 항목별 특징(늑대: 돼지 잡아먹기, 첫째·둘째: 게으름, 셋째: 생존본능·성실)`.
- **버려지는 설정 처리**: 초반에만 중요한 설정은 인트로에, 반복 상기할 설정은 대화예시에.
- **세계관을 여러 항목에 분산**: 세계관 항목에만 두지 말고 상황·말투·캐릭터 특징에 녹여 쓰면 어느 항목을 읽든 세계관을 참조해 고정률이 오른다.
- **반복 용어 묶기**: 「미초아칸 카르텔」 → 하위 항목(미초아칸주 장악 / 악명 / 라이벌 로스페로스와 10년 분쟁)으로 정리.

**[커뮤니티] 제페토 공식 세계관 예시 구조**: "기본 설정 + 스토리 배경"으로 분리. 예: 조선 궁궐 로맨스 — 신분제, 남장 의녀, 세자를 만나 궁을 빠져나가야 하는 목표, 정체 발각 시 역적, 궁 안의 세력 다툼([제페토 가이드](https://docs.zepeto.me/studio-guide-kr/vGiCQi0wcDyXTl3S6Kv-1)).

**[종합] 세계관 블록 템플릿**
```
# 세계관
- 시대/장소: 2026년 서울 을지로 / 또는 "가상 왕국 아르덴, 중세 후기 수준"
- 핵심 규칙(3줄 이내): 마법은 대가를 요구한다 / 신분제 존재 / 현대 문물 없음
- 지금 이 이야기의 긴장: {{user}}는 ○○이고, {{char}}는 ○○를 숨기고 있다
- 금지: 현대 음식·기기·인터넷 언급 금지 / 죽은 인물 부활 금지
(지명·조직·역사 상세는 로어북으로)
```

### 2-4. 상황 설정(시작 상황) 쓰는 법

- **[공식] 크랙**: 캐릭터마다 시작 설정 최소 1개, 여러 개 추가 가능. "로맨스물이라면 학창 시절/대학 시절/결혼 이후처럼" 상황별 시작점([크랙 시작 설정](https://help.crack.wrtn.ai/guide/user/tutorial/story/3)). **시작 설정 3개는 합쳐지지 않고 하나만 선택**됨 → 세계관 팩션별 시작점에 활용([뤼튼갤 76734](https://gall.dcinside.com/mgallery/board/view/?id=wrtnai&no=76734)) [커뮤니티].
- **[공식] 케이브덕 에피소드**: 캐릭터당 최대 3개, 각 10,000자. 에피소드마다 **비밀 설정과 문체 가이드를 따로** 줄 수 있어 같은 캐릭터를 소꿉친구/적/직장 상사 등 다른 관계로 시작시킬 수 있다.
- **[공식] 러비더비 '씬'**: 제목·목표·시작 상황·배경 이미지를 설정, 호감도 단계에 따라 씬/스토리/이미지 해금 가능(나무위키).
- **[커뮤니티] 시작 상황은 휘발된다**: 뤼튼갤 테스트 기준 30~50턴 지나면 시작 상황 프롬프트가 사라지므로 "초반에만 필요한 내용"만 넣고, 중심 설정은 반드시 상세 프롬프트에 둔다. 상태창·줄바꿈처럼 초반 응답의 기강을 잡는 요소에 유용([76734](https://gall.dcinside.com/mgallery/board/view/?id=wrtnai&no=76734), [69098](https://gall.dcinside.com/m/wrtnai/69098)).
- **[종합] JanitorAI Scenario 원칙**: 항상 유효한 정보(배경·규칙)만 넣고, **현재진행형 임시 사건은 넣지 말 것** — 봇이 그 사건이 영원히 지속된다고 가정한다([튜토리얼](https://jaitutorial.uwu.ai/)).
- **[커뮤니티] 조건·분기 명시(제타 여성향갤)**: 혐관인데 "거부하면 무조건 순응"하는 문제는 단순 금지로 못 고친다. ① 사건의 변화 조건(트리거) ② 분기점 ③ 변화 후 출력 방식을 명시하고, 조건 달성/미달성 각각의 출력 예시를 준다([15348](https://gall.dcinside.com/mini/board/view/?id=zetaw&no=15348)).

## 3. 캐릭터 프롬프트(설명/페르소나) 작성법

### 3-1. 표준 구조 [종합]

국내외 가이드가 공통으로 제시하는 블록(유니챗 7블록, Xiruan 프로필 템플릿, 제타갤 생초짜용 템플릿, 제페토 공식 예시, 케이브덕 공식 항목을 종합):

```
1. 기본 정보   이름 / 나이·연령대 / 성별 / 종족 / 직업·지위 / 한 줄 정체성("이 캐릭터는 ___다")
2. 외모        첫인상, 반복 등장할 특징 2~3개, 복장, 버릇 동작
3. 성격        핵심 기질 3~4개 + 숨겨진 면 1개(모순 한 스푼) + 좋아/싫어 + 스트레스 반응
4. 말투        1인칭 / 유저 호칭 / 어미 2~3개 / 입버릇 / 말 길이 / 실제 대사 예시 2~3줄
5. 배경        출신, 현재 처지, 핵심 사건 1~2개, 목표. "현재 행동에 영향을 주는 과거만"
6. 관계        {{user}}의 역할, 첫 거리감(경계/호의/친함), 호칭, 태도
7. 관계 단계   호감도 숫자 대신 "태도·호칭·말투가 어떻게 변하는지" 경로
8. 행동 규칙   조건부 규칙("~하면 ~한다"), 비밀이 새는 조건
9. 금지사항    유저 대사·행동·감정 대신 쓰지 않기 / 모르는 정보 처리 / OOC 처리
10. 출력 형식  시점·시제, 단락 수, 대사·행동 표기, 길이
```

- 유니챗 "캐릭터 프롬프트 예시 모음"의 7블록(이름·정체성 / 성격 / 말투 / 외형 / 배경 / 관계 / 금기)과 작성 팁: 성격에 모순 하나, 말투에 실제 대사, 외형은 반복 등장 디테일 2~3개만([링크](https://www.univers.chat/guide/character-prompt-examples)).
- 제타갤 생초짜용 템플릿 항목: 기본정보(성별·나이·생일·혈액형·종족·종교·시대·직업·지위) / 외형(외모·체형·헤어·착장) / 성격·말투(성격·말투·지칭·연애경험) / 취향(선호·비호·중요시) / 관계·상황·추가설정([49507](https://gall.dcinside.com/mgallery/board/view/?id=zetam&no=49507)).
- 제페토 공식 권장 순서: 기본 정보 → 외모 → 성격 → 말투(상황별 포함) → 습관 → 기타(질투·스킨십·애정 표현 등). 공식 예시 "김창운": 호칭 설정, 나이·키, 차가운 외형, 과묵한 성격, 상황별 말투, 넥타이 고치는 습관, 질투 시 거리두기, 아플 때 찾아오는 애정 표현. 말투 항목에 **반말/존댓말 여부를 명시**.
- 케이브덕 공식 항목: 캐릭터 설명(나이·국적·외모·의상·성격·취미) / 세계관 / 에피소드별 비밀 / 문체 프롬프트 / 예시 대화.
- Xiruan 프로필 템플릿: 기본정보·성격·말투 특성·심리구조·외형·취미/특기·능력/무기/직업·버릇·관계·취향·일과·NSFW. **정보 없는 항목은 빈칸으로**(안 비우면 AI가 임의로 채움), 전연령은 NSFW 삭제([링크](https://www.postype.com/@xiruan/post/22034629)).

**[커뮤니티] 뤼튼갤 첫 제작 가이드 권장 순서**: 세계관 → 등장인물 → 중요 규칙 → 서브 규칙. 상세설정이 전체 프롬프트 비중의 절반 이상([42661](https://gall.dcinside.com/m/wrtnai/42661)).
**[커뮤니티] 제타 다인캐 우선순위**: 필수규칙 > 세계관 > 캐릭터설정 순으로 상위에 둔다. 상위 항목이 하위 전체에 영향([240088](https://gall.dcinside.com/mgallery/board/view/?id=zetam&no=240088)).

### 3-2. 포맷: 자연어 vs 마크다운 vs YAML/JSON vs W++ vs PList/Ali:Chat

| 포맷 | 평가 | 출처 |
|---|---|---|
| **자연어** | 정보가 명확히 구분돼 있으면 충분. 문학적 표현이 풍부해짐("외형: 푸른눈"보다 "바다를 닮은 푸른 눈") | 바베챗 공식, 제타갤 YAML글 |
| **마크다운(#, -)** | 가장 보편적 권장. 크랙/뤼튼갤 기본, 바베챗/투킷 권장, 유저노트도 마크다운이 잘 먹힘 | 바베챗 공식, 뤼튼갤 747946 |
| **YAML** | 들여쓰기 계층, `- ` 목록, `[a, b]` 압축. 다인캐에서도 정보 안 섞임. `&`/`*` 앵커로 글자 절약 가능하나 가끔 앵커명이 그대로 출력되는 오류 | 제타갤 23864 |
| **JSON** | 토큰 효율 낮고 모델별 편차 커서 **비권장**(바베챗 공식). 뤼튼갤은 "필요한 부분에만 섞어" | 바베챗 공식, 뤼튼갤 76734 |
| **W++** | 토큰 낭비, 쉼표 나열과 차이 없음 → **쓰지 말 것** | JanitorAI 튜토리얼 |
| **PList** | `[이름: 특성, 특성; 이름's clothes: ...]` 대괄호 세미콜론 압축. 토큰 효율 최고(1,300→599토큰 사례) | rentry kingbri |
| **Ali:Chat** | 예시 대화로 특성을 "보여주는" 스타일. PList와 병용 | rentry alichat |
| **속성: 값** | 줄글보다 AI가 정보를 찾기 쉽고 글자수 적음 | Xiruan |

- **[공식] 바베챗**: "템플릿 필수 아님. 마크다운·XML·YAML 구조를 잘 학습. JSON은 비권장" — "정보와 지시가 섞이면 답변 불안정" → `[캐릭터 정보]`와 `[출력 지시]`를 분리([기초 가이드](https://docs.channel.io/babechat/ko/articles/%ED%94%84%EB%A1%AC%ED%94%84%ED%8A%B8-%EA%B0%80%EC%9D%B4%EB%93%9C%EB%9D%BC%EC%9D%B8-%EA%B8%B0%EC%B4%88-54eebf95)).
- **[커뮤니티] 뤼튼갤 "LLM 입장 프롬프트 이해도" 실험**([73363](https://gall.dcinside.com/m/wrtnai/73363)): 한 계층 아래 항목이 3~4개를 넘으면 이해도가 급락 → 하위 계층으로 분할. 목록은 `- 항목.`처럼 기호+온점이 최선. `+`는 양쪽 띄어쓰기, `,`는 한쪽만. `:`는 뒤에만 띄움. 괄호 안 예시는 괄호 안에서 문장을 끝냄. **굵게(`**`)는 사람에겐 편하지만 LLM엔 도움 안 됨**.
- **[커뮤니티] 제타 여성향갤 기호 역할표**([16089](https://m.dcinside.com/mini/zetaw/16089)):

| 기호 | 역할 |
|---|---|
| `{{user}}` `{{char}}` | 바뀔 수 있는 항목. 다인캐에서 `{{char}}`가 오류 적음. 많이 쓰면 `# {{char}}=[캐이름]` 한 줄로 |
| `[고유명사]` `'고유명사'` | 고유명사 표시. 단일캐는 `[성이름]`으로 축약 |
| `` `백틱` `` | 다른 내용과 섞지 않고 단독 규정(보안·OOC 탈취 방지에 유용) |
| `,` `/` `.` | `,` 문장 단위 / `/` 단어 단위 / `.` 지침 마무리 |
| `=` `->` | `사과=독`(동치), `사과->독`(변화). `→`는 코드 오류 잦아 비추 |
| `"대사"` | 대사 하나에 여러 설정을 담아 성격·능력 표현 |
| `**강조**` | 핵심 1~2개에만. 남발 시 글자수 낭비 |
| `\` | 뒤 내용을 텍스트로 출력(`\*\*\[\[호감도\]\] : ♥♥♡♡♡\*\*`로 출력 형식 고정) |
| `#`/`-` 뒤 한 칸 띄움, 섹션 사이 줄바꿈 | 붙여 쓰면 해석 부담으로 오류 증가 |

- **[커뮤니티] 볼드 강조는 "해골물"?** 제타갤에서 저사양 모델은 `**볼드**`를 강조로 인식하지 못한다는 결론. 대안: 반복, 영문 대문자+특수기호, `# MUST!:` 같은 항목 제목([165757](https://gall.dcinside.com/mgallery/board/view/?id=zetam&no=165757)). 크랙 유저노트에서도 `MUST FOLLOW`, `OVERRIDE ANOTHER RULES` 제목 관행([뤼튼갤 747946](https://gall.dcinside.com/mgallery/board/view/?id=wrtnai&no=747946)).

**PList + Ali:Chat 템플릿 (rentry 원형, 영문)**
```
[{{char}}'s persona: trait, trait, trait; {{char}}'s clothes: blouse(mint-green)/shorts(denim); {{char}}'s body: hair(light blue, short, messy), eyes(amber); Genre: slice of life; Tags: school, childhood friend; Scenario: {{char}} meets {{user}} at the club room after a year.]
<START>
{{user}}: Describe yourself.
{{char}}: *Yujin shrugs, not quite meeting your eyes.* "Second year. Same club as you, apparently." *She fiddles with the vending-machine coffee.* "…Didn't think you'd come back."
```
- 규칙(kingbri MinimALIstic): PList는 하나로 묶기(여러 개면 대괄호 누출), 라벨은 `Character` 대신 `Character's persona`, **리스트 뒤쪽 특성이 더 무겁게 반영**, `:`와 `=`는 호환되나 `:`가 더 널리 지원. Ali:Chat 예시는 긴 것 2개(7~8줄) 또는 짧은 것 3개(5~6줄), 총 300~600토큰 소프트 리밋. 예시마다 캐릭터 이름을 최소 1회. PList는 SillyTavern에서 Character's Note(Author's Note, depth ≈4)로 옮기면 영향력이 세진다([kingbri](https://rentry.co/kingbri-chara-guide), [alichat](https://rentry.co/alichat)).

### 3-3. 토큰 절약

- **[공식] 케이브덕**: 토큰 단위 계산, "단어 위주로 작성하면 글자 제한에 유리". 상태창은 위젯으로 처리하면 본문 분량을 아낀다(나무위키).
- **[종합]** 영구 토큰(설명·성격·시나리오)만 기억을 깎고, 첫 메시지·예시 대화는 대화가 길어지면 잘려 나간다(SillyTavern 공식, Ali:Chat). → **말투·연출은 예시 대화/첫 메시지에, 사실 정보는 설명에**.
- **[커뮤니티]** PList 압축: `blouse(mint-green)/shorts(denim)`, 예시에서 "showing a disgusted face"→"looking disgusted", 고유명사 외 소문자, 같은 감정 반복 금지(kingbri).
- **[커뮤니티] 제타갤**: 세계관 압축법(2-3절), 대화예시에 "유저가 잘 쓰지 않을 대사"만 넣어 반복 방지.
- **[커뮤니티] 뤼튼갤 예시대화 4개 이상 넣기 트릭**: 예시 칸 1개의 유저 발화 부분에 원래 포맷(`user:` / `{{char}}:`)을 그대로 흉내 내 짧은 가짜 예시를 여러 개 이어 붙인다. 토큰이 늘고 우선순위는 낮지만 칸 수 제한을 우회([25569](https://gall.dcinside.com/m/wrtnai/25569)).

### 3-4. 한국어 vs 영어 프롬프트

- **[커뮤니티] 혼용 금지**: 한 프롬프트 안에 한국어·영어·중국어를 섞으면 문맥 이탈·엉뚱한 언어 출력 확률 증가(Xiruan). 용어도 통일(뤼튼갤 76734).
- **[커뮤니티] 영문 권장파**: AI가 영문을 가장 잘 이해하므로 토큰 제한 플랫폼에서는 **영문 Markdown/YAML 변환** 추천. 변환 프롬프트: "해당 정보를 영어로 번역해서 Markdown/YAML 방식으로 구성해줘"(Xiruan). 제타갤 말투 교정 프롬프트도 "일관성을 위해 영어 작성 권장"([500080](https://gall.dcinside.com/mgallery/board/view/?id=zetam&no=500080)).
- **[커뮤니티] 한글 유지파**: 제타갤 생초짜 가이드 저자는 영문 프롬프트를 "추천하지 않음". 뤼튼갤은 "한글은 토큰 소모가 크지만 한자 전환은 오히려 효과가 떨어졌다".
- **[공식] 케이브덕 로어북 다국어 이슈**: 키워드를 `모국어|영어`로만 쓰면 다른 언어 사용자의 대화에서 로어북이 안 걸릴 수 있음(포스타입 킹크랩 정리). 영문 키워드는 **대소문자 모두 등록**(Xiruan). SillyTavern은 기본 대소문자 무시, "Match whole words"는 띄어쓰기 없는 언어(일/중)에서 꺼야 함 [공식].
- **[종합] 실무 권장**: 지시문(규칙·출력 형식)은 영어 대문자 헤더(`# MUST FOLLOW`)로, 말투·대사 예시는 **반드시 한국어**(어미·호칭은 번역 불가). 한국어 출력을 원하면 "모든 출력은 한국어로"를 명시.

### 3-5. 모델별 차이 (GPT / Claude / Gemini / 자체모델)

- **[공식] 케이브덕 모델 라인업(2026-09)**: Claude Opus 5/4.7/4.6, Sonnet 5/4.6, GPT-5.4, Gemini 3.1 Pro/2.5 Pro/3.8·3.7 Flash, DeepSeek V4/V3.2, 자체 Donald 2(기억력 특화)/Momo/Huey, 단문용 Breeze. 채팅방마다 모델 선택·대화 중 변경 가능. "모델마다 가격·문체·검열 수준이 다름. Claude 5와 Gemini 3.7이 검열 특히 엄격"(나무위키).
- **[공식] 러비더비 고급 모드**: Gemini 3.1 Pro/3.0 Flash, Claude Opus 4.7/Sonnet 4.5/Haiku 4.5, GPT 5.5(나무위키).
- **[커뮤니티] 크랙 모델별 특성(뤼튼갤 플레이 가이드 1편, 2025-10)**([747571](https://gall.dcinside.com/mgallery/board/view/?id=wrtnai&no=747571)):
  - 파워챗+(Gemini 2.5 Pro 기반): 문체·상황 유지력 최고, 그러나 **유저 사칭(유저 대사·행동 대신 서술)이 심함**, 자주 터짐.
  - 슈퍼챗1.5(Sonnet 4.0): 저렴, **긍정 편향**, 제작자 프롬프트·유저노트를 잘 따름.
  - 슈퍼챗2.0(Sonnet 4.5): 나데나데(다정) 표현에 적합.
  - 하이퍼챗: 제작 생산성 용도. 로판공방은 "초반 5~10턴 하이퍼챗 → 프로챗, 말투 무너지면 혼용"([포스타입](https://www.postype.com/@yerielleropan/post/19187537)).
- **[커뮤니티] 글로벌 블로그 관행(2026)**: Claude는 "You are [Character]" 식 빙의 프레이밍보다 **작가(author) 프레이밍**("You are a skilled author collaborating on an interactive story")에 잘 반응하고 4th wall 붕괴가 적음. Gemini는 구조화된 프롬프트·명시적 제약에 강함. GPT는 콘텐츠 정책이 상대적으로 엄격. Llama계는 짧고 선언적인 지시([RP|Fiend](https://rpfiend.com/how-to-write-a-system-prompt-for-ai-roleplay/), 검색 종합). "리더보드보다 **자기 카드로 직접 모델별 테스트**"가 공통 권고.
- **[커뮤니티] 제타 자체 모델(Zeta/Koji)**: 볼드 강조 미인식, 기본 모델이 과도하게 길게 쓰는 경향 → "출력 길이 정상화" 프롬프트(역할=간결한 시나리오 작가, 나레이션 1줄+대사 1줄, 따옴표·별표·메타발언·이모지·사과 금지) 공유([665098](https://gall.dcinside.com/mgallery/board/view/?id=zetam&no=665098)). 나무위키: "폭력적이면 '캐릭터는 부드럽고 평화로운 성격이다'처럼 **원하는 성격을 긍정문으로**" 보정.
- **[종합] 긍정형 지시 원칙**: 금지문("~하지 마")보다 원하는 행동을 서술("They notice the cold air, not embarrassment")하는 편이 모델 전반에서 안정적(RP|Fiend 저자 댓글, 제타 나무위키, 바베챗 "출력 금지라고 적어도 모델은 그 이미지를 후보로 인식" 사례).

### 3-6. 말투/어미 고정 방법 [종합]

유니챗 "캐릭터 말투 설정법"의 5요소([링크](https://www.univers.chat/guide/character-speech-style)) + 국내 커뮤니티 공통:

```
# 말투
- 1인칭: 나 / 저 / 본인 이름
- {{user}} 호칭: "선배" (친해지기 전) → "너" (관계 단계 3 이후)
- 어미: "~거든.", "~잖아.", "…그래." (2~3개로 제한)
- 입버릇: 말 끝에 "뭐." 붙이기, 당황하면 "아, 아니…"
- 말 길이: 평소 한두 마디. 검술 얘기만 나오면 길어짐
- 유저가 반말을 써도 {{char}}의 존댓말은 유지
- 예시 대사:
  "딱히 너 주려던 거 아니거든. …그냥 남은 거야."
  "선배, 거기 서 계시면 지나가기 불편해요."
```

- "츤데레", "다정" 같은 **형용사만 쓰면 그 유형의 평균 말투**가 나와 개성이 사라진다. 실제 대사 2~3줄이 어미·리듬·온도를 그대로 전달한다(유니챗, isekaizero 케이브덕 정리 "말투는 성격 설명보다 대사 예시 3~5줄").
- **말투가 흔들리는 건 어미보다 호칭**인 경우가 많다 → 호칭을 단정적으로 고정(유니챗). 일본어권 제타 가이드도 "1인칭·2인칭 호칭 결정이 가장 중요"([note.com](https://note.com/zenryokuhaisou/n/n8c5033e5974f)).
- 사용자가 반말하면 모델도 따라가는 현상 → "사용자가 반말을 해도 캐릭터 말투 유지" 예외를 명시(검색 종합).
- **모순 한 스푼**: 평소 단답인데 특정 주제에서 길어진다 / 당황하면 존댓말이 무너진다 등 "말투가 깨지는 순간" 한 줄로 입체감.
- 나레이션 지칭 고정: 여캐를 '그'로 부르면 '그녀'/이름으로 지칭하도록 지정([제타갤 38386](https://gall.dcinside.com/mgallery/board/view/?id=zetam&no=38386)).
- 사투리·특수 말투: 충청도 사투리 프롬프트, 해요체·냥냥체 등 말투 유형명을 검색해 규칙+예시로 적용(제타갤).
- 케이브덕 **문체 프롬프트** 칸은 "한두 문장이면 충분": 예 "대사는 짧게", "턴당 최대 5줄", "사용자의 대사나 행동은 임의로 생성하지 않음" [공식].
- [커뮤니티] 수식형 교정 프롬프트(제타갤 500080): `Q=0.422x+0.422y+0.155z` (x=성격, y=말투, z=배경) 가중치로 서술하라는 영어 지시. 효과는 저자 실험 수준.

### 3-7. 캐릭터 붕괴(OOC) 방지

- **[공식] SillyTavern 구조적 장치**: Character's Note(깊이 지정 주입, 보통 depth 1~5)에 핵심 특성을 넣어 매 턴 상기; `post_history_instructions`(대화 뒤에 붙는 지시)로 드리프트 억제([공식 문서](https://docs.sillytavern.app/usage/core-concepts/characterdesign/), [Chub](https://docs.chub.ai/docs/the-basics/character-creation)).
- **[종합] 규칙 작성 요령**(mini-tavern 2026 가이드): 핵심 앵커 3~5개 → 각각을 명령문으로. "Elena is usually cryptic"(약함) → "Elena must never give a straight answer. She always replies with a riddle"(강함). 규칙은 **5~10개 이내**, 시스템 프롬프트와 모순 금지, 관계가 바뀌면 규칙도 갱신([링크](https://blog.mini-tavern.com/blog/how-to-write-sillytavern-character-card-rules-the-ultimate-guide-to-roleplay-rul-13213e)).
- **[커뮤니티] Xiruan "출력 규칙" 섹션**: 프롬프트 상단에 `# 출력 규칙`을 두어 시스템 차원에서 통제. 예: `{{user}}`의 대사·행동을 대신 묘사하지 않기 / 에피소드가 늘어지면 다음 날로 스킵. **역할극 중 OOC로 AI를 불러 통제하는 건 비추천**(몰입 깨지고 메타 발언을 학습).
- **[커뮤니티] 제타갤 필수 프롬프트 6종(2026-04)**([949794](https://gall.dcinside.com/mgallery/board/view/?id=zetam&no=949794)): ① 짧은 출력 유지 ② 제3자 난입 금지(허용된 인물만) ③ 유저 대사 복붙 금지 ④ 내레이터 출력 금지 ⑤ 출력 300자 이내 ⑥ 특수문자 도배 금지(♡, ☆, …, !!!!!!, ?????, —).
- **[커뮤니티] 뤼튼갤 상세설정 지시 예**: 긍정편향 금지, 캐릭터성 충실, OOC 금지([69098](https://gall.dcinside.com/m/wrtnai/69098)).
- **[커뮤니티] 조건 미명시가 붕괴 원인**: "거부하면 순응"은 변화 조건·분기·변화 후 출력 방식을 적어야 해결(제타 여성향갤 15348).

### 4-2. 키워드 설계 [종합]

1. **흔한 단어 금지**: '회사', '대표', '커피', '그', '이', '저'는 엉뚱한 턴에 호출돼 다른 엔트리를 밀어낸다(투킷, 유니챗). 일상적으로 적용될 정보는 로어북이 아니라 캐릭터 설정에.
2. **너무 구체적·긴 복합어도 금지**: 실제 대화에 안 나온다. "투킷 대표", "탈출 계획"처럼 **정확한 고유명칭 또는 캐릭터 고유의 비밀 명칭**이 이상적(투킷).
3. **유저가 실제로 칠 말**을 포함: "바, 술집, 가게, 이 집, 사장님 가게"(유니챗 '서진의 바' 예시).
4. **동의어·별칭·연관어 묶기**: SillyTavern `Mossford,town,moss`; 루나톡 예 `과거, 기억, 트라우마, 괴롭힘, 왕따`. 케이브덕은 `|`로 구분.
5. **대소문자**: 영문은 대소문자 둘 다 등록(Xiruan, 케이브덕). ST는 기본 무시, 옵션으로 민감.
6. **지문 기호를 키워드로 쓰지 말 것**(`.` `*` — 제타 공식 경고).
7. **부분 일치 주의**: 크랙 키워드북은 텍스트 일부만 일치해도 작동 → 짧은 키워드는 오발동(뤼튼갤 69098). ST "Match whole words" 기본 켜짐.
8. **2차 키/AND 로직**(ST, kingbri): 1차 키 + 2차 키 동시 존재 시만 활성 → 오발동 억제.
9. **다국어**: `모국어|영어`만으로는 타 언어 유저에 미발동 — 상태창에 로어북 관련 단어를 영어로 적게 하는 우회(킹크랩, 임시방편).

### 4-4. 상시 활성 vs 조건 활성, 우선순위·삽입 위치

- **상시(constant)**: ST 🔵, CCv2 `constant:true`, Elyn "찾았을 때 비활성화"(시작부터 켜짐→키 등장 시 꺼짐: 반전·비밀 공개용), 크랙 "트리거 없으면 상단 3개가 상시 활성"(이를 이용해 **상위 3개를 추가 프롬프트 칸**으로 쓰는 응용 — 뤼튼갤 76734).
- **우선순위**: 케이브덕·크랙·바베챗·루나톡 모두 **목록 상단 우선** → 정체성·행동 원리에 치명적인 정보일수록 위로(투킷의 '대표와의 계약' 6번째 누락 사례). Elyn 0~255 숫자. ST `Insertion Order` 숫자가 클수록 컨텍스트 끝(=영향력 큼)에 삽입.
- **삽입 위치(ST)**: Before Char(중간 영향) / After Char(큰 영향) / 예시 대화 전후 / AN top·bottom / @Depth(0=맨 아래, 역할 system·user·assistant 선택) / Outlet. "중요할수록 아래에, 단 과하게 높이면 누출(leakage)".
- **크랙 키워드북 3개 제한 공략**([30440](https://gall.dcinside.com/m/wrtnai/30440)): ① 우선순위 낮은 항목(마을)을 맨 아래 ② 비슷한 역할 묶기(포션+무기, 마을+던전) ③ 스토리 키워드는 초반 스토리일수록 아래(다음 스토리용을 먼저 읽게). 둘을 조합하면 키워드 20개도 안정.
- **검색 범위/스캔 깊이**: Elyn 0(현재 입력만, `!마법` 커맨드형)~전체 히스토리(장기 이벤트); ST scan depth 기본 2(WI 백과 저자는 4); 루나톡 1 권장.
- **그룹/의존성**(Elyn): 관계 단계(적대→중립→호감→연인)를 한 그룹으로 묶어 상위 우선순위 하나만 적용; 세계→지역→인물 의존 체인으로 무관한 언급에 인물 로어가 딸려오는 것 방지.
- **타이밍 효과**(ST): sticky(N턴 유지), cooldown, delay(대화 N턴 이후 활성). CCv3 `@@activate_only_after`, `@@activate_only_every`.

### 4-6. 자주 하는 실수 [종합]

1. 흔한 키워드로 오발동 → 중요 엔트리 밀림 (투킷·유니챗)
2. 동시 활성 상한(크랙 3/바베챗 5/케덕 10)을 모르고 **중요 항목을 아래에** 둠 → 누락
3. 로어북에 캐릭터 기본 정보·이미지 링크 넣기(루나톡)
4. 한 엔트리에 모든 설정 몰아넣기(3,000자 초과) / 대화에 안 나올 단어("세계관")를 키로
5. 캐릭터 간 관계를 세계관 문서에 쓰기(→ 각 캐릭터 프롬프트로)
6. 세계관 탭에서 **연결을 안 함**(유니챗) / ST에서 **내장 로어북 임포트를 거절**(카드 임베디드 로어북은 임포트 전까지 비활성)
7. 검색 범위 불일치(짧게 끝나야 할 설정이 계속 남거나, 장기 이벤트가 2턴 만에 꺼짐) (Elyn)
8. 상호 배타 항목을 그룹으로 안 묶음 → 적대 로어와 연인 로어가 동시 삽입 (Elyn)
9. 과도한 "상시/고중요도" 지정 → 누출·토큰 낭비 (WI 백과 "overimportance")
10. PList를 여러 개 흩뿌려 대괄호 누출; 평문 WI가 PList 사이에 들어가 대사로 오인 (WI 백과)
11. 테스트 채팅에서 발동/해제를 확인하지 않고 공개 (Elyn 체크리스트)
12. 크랙: 챗봇이 말한 키워드는 **다음 턴부터**, 유지 안 되면 꺼짐 → 상시 필요한 내용은 상세 프롬프트로

## 5. 첫 메시지/시작 장면(인트로) 작성법

### 5-1. 왜 가장 중요한가 [종합]

- SillyTavern 공식: "모델은 **첫 메시지에서 소통 스타일과 응답 길이**를 다른 어떤 것보다 강하게 학습한다. 원하는 스타일로 써라."
- Chub 공식: "initial message는 이후 행동을 강하게 형성하므로 신중히."
- 2026 블로그 공통: "the single highest-leverage field" — 밋밋한 두 줄 오프너는 밋밋한 두 줄 응답을 허용한다는 신호.
- 뤼튼갤: 첫인사는 "캐릭터가 한 말"로 취급돼 초반 진행에 영향, 키워드북 트리거로도 쓰임. 커스텀 템플릿에선 서식 영향이 특히 큼.
- 제타 여성향갤: "AI는 입력한 인칭·맞춤법·띄어쓰기·강조·대사 기호를 그대로 학습" → 인트로·예시에 오탈자 금지.

### 5-2. 길이

| 출처 | 권장 |
|---|---|
| 포스타입 [공식] | 최대 1,000자 |
| 케이브덕 [공식] | 에피소드당 10,000자, 나눠쓰기 시 말풍선 10개 |
| 제페토 [공식] | 나레이터/유저/캐릭터 발화 단위로 추가, 추천 답변 3개×100자 |
| 유니챗 | **3~6문장** |
| Tikita 입문 가이드 | 길게보다 상황·감정·원하는 톤을 짧게 |
| JanitorAI 튜토리얼 | "긴 첫 메시지는 긴 답변을 유도" — 원하는 답변 길이에 맞춰 |
| 제타 여성향갤 | 장문 선호 시 2~4페이지도 가능하나 턴이 지나면 밀도 저하; 단문은 상황 묘사를 함축적으로 |

→ 실무: **원하는 턴당 응답 길이의 1~1.5배**로 쓴다. 유저가 3~5문단 응답을 원하면 인트로도 3~5문단.

### 5-3. 구조 공식

**유니챗 3요소**([첫 메시지 예시](https://www.univers.chat/guide/first-message-examples)): ① 상황 설정(장소·시간·분위기) ② 캐릭터 등장(무엇을 하는지, 말투·성격이 드러나는 행동과 대사) ③ **공 넘기기**(질문·시선·다가오는 행동으로 유저가 반응할 여지). "첫 메시지가 스스로 완결되면 유저가 받아칠 거리가 없다."

**JanitorAI 튜토리얼**: 캐릭터가 어디서 무엇을 하는지 → 핵심 특성(사투리·초능력) 부각 → 유저가 반응할 거리 → **유저 행동을 직접 서술하지 말 것**: "You pick up…" 대신 "Character sees {{user}} pick up…".

**Ali:Chat / kingbri**: 2인칭으로 초안을 쓴 뒤 역할을 뒤집어 **캐릭터가 행동을 수행**하고 유저 행동은 모호하게; 루프 방지를 위해 **유도 질문(leading question) 제거**; 예시 대화의 마지막은 첫 메시지와 겹치게(연결감).

**제페토/캐럿 [공식] UI 구조**: 나레이터(상황) → 캐릭터(대사) → (유저 추천 답변 최대 3개). "나레이터로 상황을 묘사하고 캐릭터 대사를 넣는 방식 권장".

**템플릿**
```
*[장소·시간·감각 1~2개]. [{{char}}가 하고 있던 행동].*
*[{{user}}를 인지하는 순간의 반응 — 시선·망설임·표정].*
"[말투가 또렷한 첫 대사 — 호칭·어미 포함]"
*[반응 여지를 남기는 행동 — 손을 내밀거나, 자리를 비우거나, 묻는다].*
```

**예시(유니챗 Before/After 요지)**
- Before(나쁨): 캐릭터 자기소개 + 환영 인사 + "따뜻한 라떼 좋아하시죠?"처럼 **유저 취향까지 정해버림**. 개성 없음, 받아칠 거리 없음.
- After(좋음): 시간·분위기를 살리고, 캐릭터의 어수룩한 행동과 말투를 보여준 뒤 질문으로 마무리. 유저 행동은 쓰지 않음.

### 5-4. 시점(1인칭/2인칭/3인칭)

- **3인칭 제한 시점**이 글로벌 기본값(RP|Fiend 베이스 템플릿: "Write in third-person limited unless the card specifies"). 유니챗: 3인칭 또는 1인칭 중 택일 후 세션 내내 일관.
- **1인칭 나레이션 만들기(제타갤)**: 별도 프롬프트 없이 **인트로를 1인칭으로 바꾸면** 이후 대화도 1인칭으로 나옴. "{{char}}가 문을 열었다." → "나는 문을 열었어."([195063](https://gall.dcinside.com/mgallery/board/view/?id=zetam&no=195063)). 로판공방: 유저노트에 기본 지침 + "캐릭터 1인칭 시점 서술" OOC로 전환.
- **2인칭("당신/너")은 혼동 위험**: 케이브덕 스냅샷 테스트에서 1인칭·2인칭 서술은 캐릭터와 유저 묘사를 혼동(특히 동성)([포스타입](https://www.postype.com/@untitled-record/post/20400359)). kingbri는 2인칭으로 초안 후 역할 뒤집기.
- 바베챗 공식 예: "3인칭 전지적 시점, 캐릭터의 내면 심리 중심, 은유법 사용, 형이상학적 표현 회피"처럼 **시점+서술 중심+표현 기법**을 명시.

### 5-5. 분위기 설정

- 장면 감각 목록(빛·소리·냄새·촉감)을 프롬프트에 미리 적어두고 인트로에서 2~3개 사용(유니챗).
- 시대 고증: 인트로에 현대 문물이 섞이면 이후 전부 오염 → 세계관 금지 규칙과 일치시킨다(와따).
- 제타 여성향갤: 인트로에서 **내레이터/유저/캐릭터 역할을 섞지 말 것** — AI가 역할을 혼동.
- 뤼튼갤: 첫인사 머리말에 `#`을 쓰면 첫 응답에 시스템 메시지가 과도하게 출력된 사례.

### 5-6. 여러 시작 장면 활용 [공식]

- 크랙: 시작 설정 여러 개(상황별), 하나만 선택됨.
- 케이브덕: 에피소드 3개, 각각 **비밀·문체 가이드 별도**.
- SillyTavern/CCv2: `alternate_greetings` 배열 → 첫 메시지 스와이프. 그룹챗에서는 랜덤 선택, CCv3 `group_only_greetings`.
- 러비더비: 크리에이터 씬 + 호감도 해금 씬.
- 활용 패턴: 관계별(소꿉친구/적/상사), 팩션별, 시간대별(학창/대학/결혼 후), 유저 성별/페르소나별, 난이도별(혐관 시작 vs 호감 시작).

### 5-7. 잘 된 첫 메시지 분석 포인트 [종합]

1. 첫 문장에서 **장르와 시대**가 보이는가(감각 디테일 하나로).
2. 캐릭터의 **말투가 첫 대사에서 고정**되는가(호칭·어미).
3. 유저의 행동·대사·감정·취향을 **한 줄도 쓰지 않았는가**.
4. **열린 비트**로 끝나는가(완결된 장면 X, 유도 질문 남발 X).
5. 인트로가 **이후 응답의 길이·형식(별표/따옴표/단락)**의 본보기인가.
6. 로어북 키워드가 자연스럽게 1~2개 들어갔는가(크랙은 첫인사 키워드로 첫 응답부터 발동).
7. 공개 소개글과 톤이 일치하는가(한줄소개에서 약속한 훅이 인트로에 바로 나오는가).

**유니챗 발행 전 체크리스트**: 유저 행동·대사·감정 미서술 / 3요소 충족 / 첫 대사에 말투 / 3~6문장 / 시점 일관.

## 6. 예시 대화 작성법 및 효과

### 6-1. 효과와 위치 [종합]

- Character.AI 공식: "AI는 형용사 한 단락보다 **잘 쓴 대화 한 번**에서 더 많이 배운다." 긴장된/캐주얼/예상 밖 등 톤의 **폭**을 보여주고, 각 교환마다 다른 유저 이름을 쓸 것([공식 가이드](https://support.character.ai/hc/en-us/articles/50609183646875-5-Character-Definition)).
- SillyTavern 공식: `<START>`로 블록 구분, `{{char}}:`/`{{user}}:` 라벨. 컨텍스트가 차면 **블록 단위로 뒤에서부터 탈락**(옵션으로 고정 가능). 텍스트 완성 API에선 Example Separator로, 챗 완성 API에선 "New Example Chat" 유틸 프롬프트로 치환.
- Ali:Chat: 예시 대화는 **"임시"** 토큰(기억을 깎지 않음)이지만 영향력이 커서 성격을 예시로 표현하는 전략이 성립. 예시에서 동사 반복 피하고 동의어 사용, 몇 문장마다 캐릭터 이름 언급, 긴 예시는 긴 응답을 유도.
- 케이브덕 [공식]: 예시 대화 **"항상 적용"**(말투·기본 반응) vs **"상황에 따라 적용"**(현재 대화와 의미적 유사도가 높을 때만 — 특정 주제 반응). 플레이어에게 공개 가능.
- 크랙 [공식]: 고급 설정에서 최대 3개. 뤼튼갤: "영향력 매우 큼. 글머리 기호형/문장형/행동·감정 묘사형에 따라 출력 방식이 달라짐".
- 포스타입 [공식]: 대화 예시 1,000자, 상황별 말투·감정이 구체적일수록 몰입감.
- 제페토 [공식]: 최대 10개, "특정 상황에서 캐릭터가 이렇게 답하면 좋겠다" 방식.
- JanitorAI: 선택이지만 권장, personality 칸 안에 "greeting example" 형태로 넣어도 됨.

### 6-2. 작성 원칙

1. **대사 반복 함정**: 예시를 잘못 쓰면 예시 대사만 반복 → **유저가 잘 쓰지 않을 법한 대사**, 혼잣말·드문 상황으로(제타갤·이루다갤). 뤼튼갤: "과하게 의존하면 같은 패턴 반복". 2026 블로그: 모든 예시가 같은 행동으로 끝나면 그걸 물고 늘어짐 → 3~5개를 **서로 다른 무드**(호기심/엄격/즐거움/가르침)로.
2. **예시에 행동·심정 넣기**: 행동 묘사와 심정을 적으면 실제 대화에서도 그 표현이 늘어남(제타갤 38386). 별표로 행동/대사/의성어/심정을 구분.
3. **역할 분담을 보여준다**: 캐릭터가 "다음 행동을 제안하고 멈추는" 예시로 유저 대역을 막는다(crushon.ai 디버깅 글). 유저 대신 답하는 예시는 제거.
4. **첫 메시지와 톤·길이 일치**, 마지막 예시는 첫 메시지와 겹치게(Ali:Chat).
5. **포맷 통일**: `{{user}}: "..."` / `캐릭터명: *행동* "대사"` (Xiruan). 플랫폼 UI가 발화자 선택형(제페토·케덕 나눠쓰기)이면 그에 맞춤.
6. **가독성**: 예시가 난잡하면 정보도 난잡(제타갤).
7. **제작 보조**: 상황 5가지를 AI에게 요청해 초안 생성 후 캐릭터 대사로 다듬기(Xiruan), 제타갤 "간단 상세정보 프롬프트"(캐릭터 설명 → 말투 예시 불릿 생성기, "좀 조련하면서 해야 타율 좋음").

### 6-3. 템플릿

```

## 7. 유저 페르소나 / 유저노트 활용

### 7-1. 플랫폼 사양 [공식]

|---|---|---|
| 크랙 | 대화 프로필(이름·외모, 100자 이내) | 500자 무료 / 매 채팅 10크래커로 2,000자. 마크다운 권장 |
| 케이브덕 | 페르소나(이미지 포함) | 유저 노트 1,500자(윙 사용 3,000자), 구 장기기억 기능 통합. 위젯 캐릭터는 위젯 입력칸과 한도 공유 |
| 제타 | 대화 프로필(제작자가 유저 역할을 설정, 비주얼 노벨 500자) | — |
| 바베챗 | 페르소나(`<my_role>` 최상단 → **제작자 프롬프트보다 우선**할 수 있음) | 유저노트(약하지만 AI 지시는 강하게 작용) |
| 러비더비 | — | 유저노트(채팅방별, "캐릭터가 항상 알아야 할 유저 정보") + 메모리 |
| SillyTavern | Persona(설명 + persona lore 연결) | Author's Note(`/note`, 깊이·주기 설정) |

### 7-2. 페르소나 작성 [종합]

**유니챗 5줄 양식**([페르소나 만드는 법](https://www.univers.chat/guide/persona-setup)):
> 이름: {불릴 이름 / 호칭. 본명 아니어도 됨}
> 성격: {핵심 기질 2~3개. 예: 무뚝뚝하지만 챙김, 호기심 많음}
> 말투: {반말/존댓말 · 1인칭(나/저) · 입버릇이나 어미 습관}
> 관계: 상대 캐릭터와 나는 {연인/동료/처음 본 사이/주종 등}, 첫 거리감은 {경계/호의/친함}
> 한 줄 배경: {지금 내 처지 한 문장. 예: 이 도시에 막 전입한 신입}

- **비워두면**: AI가 빈칸을 "편한 사이"로 채워 첫 턴부터 반말·애칭 / 매번 자기소개 반복 / 직업·과거·감정을 임의 생성.
- **관계·거리감이 가장 중요**: 이름·성격이 비어도 관계만 정확하면 대부분 잡힌다.
- 위치 유형: 주인공형(밀착) / 관찰자형(들어주는 위치) / 제3자형(이름·배경 구체적).
- 흔한 실수: 페르소나 미작성, 관계 없이 이름만, 연표·혈액형 과다, 말투를 "시크함"처럼 추상어로만.
- 로판공방: 대화 프로필엔 이름·나이·성별·외모 기본 정보, 유저노트엔 세부 설정·플레이 스타일 지침(둘을 바꿔 적어도 큰 문제 없음).
- 바베챗: 페르소나 제목은 `###`부터(상위 헤더 쓰면 AI가 프로필을 이상하게 해석), AI 지시는 프로필 아래 `##`로 주어를 분명히.
- 제작자가 미리 유저 역할을 설정(제타 대화 프로필·제페토 "주요 소비층")하면 관계극의 거리감이 안정됨. 제타 여성향갤: 대화 프로필을 **기억 노트로 활용**하는 기법 예고.

### 7-3. 유저노트 활용 패턴 [커뮤니티]

- **상시 규칙 + 필요 시 OOC 복붙** 조합(아카 뤼튼채널 126217399 요지). 유저노트는 "유저에게 내려지는 추가 프롬프트".
- 헤더 관행: `# MUST FOLLOW`, `# OVERRIDE ANOTHER RULES`(뤼튼갤 747946). 바베챗: `###` 항목(진행사항 / 캐릭터별 규칙 / 스테이터스)로 수정 편하게.
- **기억 보조**: 핵심 정보만 간추려 10~20턴마다 갱신(아카 뤼튼채널). 유저노트용 요약 JSON 생성 프롬프트(뤼튼갤 45957, 2024-12): 트리거 "유저노트" 입력 시 450자 이하·줄바꿈 없는 JSON으로 `세계관(규칙/주요사건/특이사항) / 캐릭터 목록(이름·유형·역할·특징·성격·목표·관계·비밀·능력) / 현재 상황(장소·시간·요약) / 최근 사건 / 진행 중 플롯(제목·상태·관련 캐릭터)` 출력 → 붙여넣기.
- **유저 대역 방지 규칙**을 유저노트에(로판공방 "Strict Rule", 제타갤 유저 프로필 문구):
  > # 규칙
  > - 페르소나이름의 대사와 행동 도용 금지.
  > * 페르소나이름은 {{user}}가 직접 조종함.
  ([제타갤 642545](https://gall.dcinside.com/mgallery/board/view/?id=zetam&no=642545), Gemini 계열에서 확인, "100% 아님")
- **출력 형식 보정**: 나레이션·독백 별표 감싸기 + 예시(로판공방), 분량 지침(크랙은 '최대 출력량 조절' 탭과 병행).
- **주의**: 작성 내용이 적용되지 않으면 제작자가 막아둔 경우가 많음(바베챗갤). 외부 링크로 공유되는 유저노트는 내용을 확인하고 쓸 것(일부는 검열 우회·시스템 은닉 지시 포함).

## 8. 기억력 / 장기 대화 유지 기법

### 8-1. 왜 잊는가 [종합]

- 컨텍스트 윈도우 한계: 프롬프트+예시+페르소나+최근 대화가 한도를 채우면 오래된 것부터 탈락(제타갤 21967, 유니챗 기억 시스템, isekaizero). 크랙 공식: 일정 토큰 이상이면 **중간 맥락**을 잘 활용하지 못해 기준값으로 제한 중.
- 서버 상태에 따라 프롬프트 인식률이 떨어지는 현상(뤼튼갤 69098, 로판공방 — 유저노트 무시·호칭 급변·외형 혼합·시작설정 뒤섞임이면 서버 오류 의심).
- 카드가 비대하면 최근 메시지를 밀어내 "방금 일을 잊은 것처럼" 보임(tavernsprite).

### 8-2. 플랫폼 메모리 기능 [공식]

- **케이브덕**: 메모리 탭 3단계(최근 대화 / 현재 대화 요약 / 전체 서사 요약), 요약문 직접 편집·고정, '캐릭터 상태'(감정·속마음·계획) 별도 추적, 고급 모델 사용 시 요약 모델도 상향. 자체 모델 Donald 2는 기억력 특화. "100턴 이상이면 흐름을 끊어 주는 편이 낫다"(나무위키). **반드시 기억할 설정은 로어북, 전반적 흐름은 유저노트**.
- **크랙**: 긴 대화는 요약하는 장기 기억 시스템으로 간헐적 해소. 롤플레잉은 관계, 시뮬레이션은 사용자 상태를 요약에서 중시하도록 개선 예정. 2026-05 **단축어** 기능(제작자가 스토리에 OOC/명령어 등록, 유저도 '내 단축어' 등록).
- **러비더비**: 메모리(대화 요약 기록, 중요 메모리 설정·삭제·최적화) + 유저노트.
- **제타**: 설정집은 기억 강화가 아니라 키워드 호출 방식. 대화 저장 100슬롯, "여기서부터 새로 하기", 책갈피.
- **유니챗**: 2턴마다 기억 담당 AI가 장면 상태/감정 변화/중요 사건/관계 변화/진행 중 스토리/설정 정보를 구조화해 갱신, 사이드바에서 편집.
- **SillyTavern**: Summarize 확장, Author's Note 주기 주입, Character's Note depth 주입, 벡터 스토리지(RAG), 로어북 sticky.

### 8-3. 제작자/유저 측 기법

1. **요약 OOC를 주기적으로** (로판공방, 5~10턴마다): 관계 요약 / 캐릭터의 태도·감정 / 시간순 주요 에피소드 / 현재 시점·미해결 요소 — 크랙에선 단축어로 등록. 키워드북 `!요약` 커맨드는 오류가 있어 OOC 직접 사용 권장.
2. **유저노트 갱신**(10~20턴) + JSON 요약 생성 프롬프트(7-3절).
3. **기억을 분산 저장**: 매 턴 필요 → 프롬프트 / 조건부 → 로어북(검색 범위 넓게) / 진행 상황 → 유저노트·메모리 / 초반만 → 시작 상황.
4. **짧은 턴 교환**: 장문보다 `*행동* "짧은 대사"`가 기억에 유리(제타갤 21967, 저자 추정).
5. **크랙 시작 상황은 30~50턴에 휘발** → 중심 설정은 상세 프롬프트에. 뤼튼갤: 유저노트 병행 시 캐릭터성 유지에 도움.
6. **반복 표현 발생 시**: 반복 시작 전 메시지로 삭제·롤백, 새 채팅방(로판공방). ST는 repetition penalty 1.15~1.20 + 예시 다양화(mini-tavern).
7. **Character's Note / Author's Note에 "Memory" 필드**: "Elena remembers the apprentice's name is Kael" 같은 핵심 사실을 5~10턴마다 주입(mini-tavern).
8. **엔딩 후 지루함 방지**: 캐릭터 플롯은 갈등 해소 후 떡밥을 추가 설계(제타 여성향갤). 로어북 delay/`@@activate_only_after`로 후반 이벤트 투입.
9. 운영자 관점: 일정량 대화를 요약·압축하는 방식이 비용/기억 손실의 절충(Yunha Kim).

## 9. 멀티 캐릭터 / 군상극 작성법

### 9-1. 구조 설계 [종합]

**유니챗 다중 캐릭터 템플릿**([링크](https://www.univers.chat/guide/character-prompt-multi)) 블록: 제목/무대 → 핵심 한 줄 → 역할(사용자·캐릭터들·AI) → 꼭 지킬 규칙(유저 대사 대신 쓰지 않기 / 감정은 행동으로 / **한 명만 계속 말하지 않기**) → 글 스타일 → 분량·구조 → 장면 감각 목록 → **공통 무대** → 등장인물(인물당 겉모습·속마음·말투 한 마디) → **인물 사이 관계** → **누가 언제 나오나(등장 계기)** → 첫인사.
- 깊게 다룰 인물은 **2~4명**, 단역은 이름+한 줄. 인물 설명보다 **관계에 분량**을 둔다.
- 턴 순서: 공통 장면·감각 → 상황에 맞는 인물의 행동·대사 → 다른 인물 반응 → 유저 여지.
- 샘플 '노을장 하숙집': 한겨울(깐깐한 관리인, "규칙은 규칙이에요.") / 도진(능청 취준생, "어~ 신입 왔네?") / 유나(낯가리는 막내, "...안녕하세요. (꾸벅)"). 관계: 도진은 겨울을 놀리고 겨울은 질색, 유나는 겨울을 따르고 도진은 유나를 어려워함. 등장 계기: 겨울=규칙·공용공간 문제, 도진=저녁 거실, 유나=늦은 밤 주방.

**제타 다인캐 슬롯 구조(커뮤니티)**([240088](https://gall.dcinside.com/mgallery/board/view/?id=zetam&no=240088)):
```
상세설명: 필수규칙
캐1(최상위 슬롯): 특정 캐릭터 대신 "등장인물" 포괄 설명 또는 세계관

데면데면한 존댓말 → 어색한 농담 → 옛 말투의 반말
## 첫인사

6. 예시 대화는 서로 다른 무드 3~5개, 유저가 쓰지 않을 대사로, "제안하고 멈추는" 역할 분담을 보여준다.
7. 규칙은 5~10개, 명령문, 조건·분기·변화 후 출력까지. 금지보다 원하는 행동의 긍정 서술.
8. 로어북 키워드는 "유저가 실제로 칠, 적당히 구체적인" 단어 + 별칭, 중요한 것부터 위로, 상한을 안다.
9. 기억은 분산: 프롬프트(항상) / 로어북(조건) / 유저노트·메모리(진행) / 시작 상황(초반만) + 주기적 요약.
